## v0.30：照片真 EXIF 保留 + 水印取值优先 EXIF（15:31–16:10）

用户问"压缩后的照片，经纬度等元数据是否还保存" → 答复：**不保留**（压缩是 Canvas 像素重绘，
`drawImage`→画水印→`toBlob('image/jpeg')`，管线必然丢全部 EXIF，非 bug）；但坐标没丢——
`getCoords()` 单独取定位，把 `坐标：lat,lng` + `时间：…` + `备注：…` 作为水印文字烙在画面上；
手机相册里的原图 EXIF 完整。随后用户拍板："**真 exif 保留，水印的经纬度和时间优先从相片 exif 里面提取**"。

### 方案选型（doc/017 §二）
- 原生 ExifInterface 拷贝 → 需重新出包（本机无 Android SDK）→ 不采用
- 服务器端 Pillow 注入 → App 还需额外传 EXIF 字段，复杂 → 不采用
- **★ piexifjs（MIT，pure JS）在 JS 里读写 → 改网页端即生效，无需出包** → 采用

### 实现
- `static/vendor/piexif.js`：piexifjs 1.0.6 原样引入（78KB，MIT，未改动）；**node 也能 require** → 纯逻辑可自动化测试
- `static/photo_exif.js`：**纯逻辑层**（piexif 依赖注入 → 浏览器/node 通用）：
  `exifTime`（EXIF 冒号日期解析）/ `toStamp`（水印格式）/ `exifOfDataUrl`（读 GPS+DateTimeOriginal，
  度分秒→十进制、半球取负、lat/lng 必须同时有效）/ `preserveExifDataUrl`（回写 EXIF）
- `static/app.js`：`blobToDataUrl` + `exifOf`/`preserveExif` 薄封装（**任何失败静默退回原行为**——
  EXIF 属锦上添花，绝不能因它丢照片；非 JPEG 如 HEIC 不处理）；拍照流程挂钩：
  `exifOf` → 水印坐标/时间优先 EXIF（缺失退回 `getCoords()`/当前时间）→ `drawWatermark(takenAt)` →
  `preserveExif`（此后存相册/下载/云同步用的都是这份带 EXIF 的图）
- `drawWatermark` 新增 `opts.takenAt`（Date），水印首行时间优先用 EXIF 拍摄时间
- `templates/index.html` 引入两个新脚本（在 app.js 之前）；`?v=` → **0.30**
