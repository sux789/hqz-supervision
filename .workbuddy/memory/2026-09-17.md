### 一、验收备注填了又没了（数据丢失，最高优先级）
- **根因三处叠加**（全在 `static/app.js`）：
  1. `scheduleRowSave()` **800ms 防抖**，而 `#btnBack` 直接 `nav('#/')` **不冲刷** → 0.8 秒内点返回，编辑永远发不出去
  2. 全文件**没有 `beforeunload`/`pagehide`** → 切后台/重载/被系统回收同样丢
  3. jspreadsheet 的 `onchange` 要等 blur/Enter → 用户正在输入就点返回时 `allRows` 里**还是旧值**，只补"离场冲刷"也不够
- **修复三层**：①待保存任务**快照 `{wid, ridx, values}`**（防节流窗口内切工作簿把 A 写进 B）②`flushRowSave()` 在**返回 / `route()` / `pagehide` / `beforeunload` / `visibilitychange(hidden)`** 五条路径前调用，卸载用 `fetch({keepalive:true})`（**不用 `sendBeacon`**：带不了 `X-Sup-Token` 头，令牌只能塞 URL 会进访问日志）③**委托监听 `#formEl` 的 `input`** 逐键同步进 `allRows`
- **浏览器实测**：写值 + `scheduleRowSave()` + **立刻点返回（不等 800ms）** → 服务端已落库；重新打开仍在 ✅

### 二、后台「下载 Excel」加筛选弹框
- **先纠正我的误解**：我最初理解成"导出文件里带筛选"（AutoFilter）并已动手改；用户澄清后才是正确需求 —— **后台点下载 → 弹框选条件 → 只导出符合条件的行**，且**当前工作簿没有的字段不出现在弹框里**。
- **四条口径**（用户确认）：只筛行（不筛列）；字段用**参数 sheet 声明**；日期**单日**；下拉**单选**。
- **实现**：新增可选参数 key **`导出筛选`**（控件映射，`字段|select` / `字段|date`）；`export_filters_of` 返回**声明 ∩ 该工作簿表头**（→"没有的字段不提示"）；`filter_rows` 只筛行；新增 `GET /admin/api/workbooks/<id>/filter-options`；`admin_download` 只认声明过的字段（多传的参数忽略，防"多传一个参数就把数据筛空"）；前端新增 `#filterModal` + `openFilterDialog`，下载按钮由直链改按钮。
- **顺带修好导出两件事**：①**AutoFilter 范围按实际数据重设**（原保留上传时的旧范围，行数一变就漏；源模板没设则导出后完全没筛选）②**日期列导出成真日期**（Excel 只对真日期列给「日期筛选」树），配套 `_norm_cell` 识别 `datetime/date` 还原 `'YYYY-MM-DD'`。
- **线上实测**：造林模板导出 `auto_filter.ref='A1:AC601'`（修复前为 `None`）；临时模板声明的 3 字段正确返回（标段 5 选项/乡镇 12 选项/验收日期 date），按 乡镇筛 600→52 行且全为该乡镇，未声明字段被忽略（仍 600 行）。

### 踩坑（已写入 CONSTRAINTS C14 与 doc/012 §四）
1. **只补"离场冲刷"不够** —— 还得先逐键同步进内存，否则冲刷上去的是旧值。
2. **待保存任务必须快照 wid/ridx** —— 否则切工作簿写错行。
3. **`sendBeacon` 带不了自定义头** —— 令牌只能进 URL → 落到网关访问日志。
4. **中文下拉值别用字典序** —— `六标/七标/八标/九标/十标` 按码位排会变成 `七标/九标/八标/六标/十标`；改按**数据中首次出现顺序**（表格本身已按业务序排好，且不依赖 collation 假设）。
5. **`datetime` 必须先于 `date` 判断** —— `datetime` 是 `date` 子类，且 `str(datetime)` 带 `00:00:00` 会污染数据。
6. **测试自身的坑** —— `test_unit.py` E14~E16 一度复用了别的表头的基底常量（`FULL` 的占位符属于 `HEADERS`），先被"占位符不是表头"拦下，测不到 `导出筛选` 的校验分支；**每套用例要用与自家表头匹配的基底**。

## v0.26：后台「更新 Excel」按唯一键就地合并 + 回滚（09:50–10:10）

用户提问："在下载 Excel 按钮下面加『更新 Excel』，如果有唯一键、唯一键有一定比例重合，可以更新或添加一定量的值，是否合理？用于解决填到一半修改 excel、或者添加 导出筛选 等等。"

### 先查出两个事实（决定了方案）
1. **重新上传不覆盖**，永远新建（实测 ids `[2,3]` → `[2,3,66]`），旧的连同已填数据原样保留 → "数据丢失"其实是**变成两个工作簿**。
2. **导出的 Excel 自带「参数」sheet**（实测 sheets=`['中幼林抚育验收','参数']`）→ "下载→改参数→重传"这条迂回路径**本来就存在**，只是会多出一个工作簿、要手动清旧的。
→ **真痛点是工作簿 id 变了**：`accept_logs` 绑 `workbook_id + row_idx`、下架状态、App 使用习惯全断链。

### 判断：方向合理，两处改法（用户四项全按推荐确认）
- 不用"重合比例"当**自动闸门**（删掉一批小班后重合率很低但仍是同一份数据；传错文件也可能凑巧重合）→ 改为**预览统计 + 输入工作簿名确认**。
- **保留原工作簿 id**（否则和重新上传没本质区别）。
- 冲突取值：**App 已填优先**；旧表没有的行**保留**。

### 我做的一处必要细化（否则功能达不到目的）
"App 已填优先"若理解为**所有列**旧值优先，则用户在新 Excel 里改的 `小班面积`、修正的原始数据、新增列的取值**永远不生效**。故收窄为：
> **只有「可编辑列」（旧表∪新表）旧值非空优先；其余列以新表为准。**

### 实现
- `param_parser.py::merge_rows()` 纯函数（+ `_keep` 保留数值类型 / `_txt` 比较取键）：以**既有行顺序**为基准原地合并（老行 row_idx 不变 → 日志不错位）、新表多出的行追加末尾、按**列名**对齐（可增删换序）、统计 `matched/added/kept_old_only/conflicts/blanked_nonempty/dropped_nonempty/dup_new_key_count`。
- `main.py`：新表 `workbook_backups`（每簿最多 `MAX_BACKUPS=5`，同时备份源模板文件）、`POST /api/workbooks/<id>/update`（`?dry=1` 只算不写 / 正式提交需 `confirm=<工作簿名>`）、`POST /api/workbooks/<id>/rollback`、`admin_list` 加 `can_rollback`。
- 前端：后台行内加「更新 Excel」按钮 + `#updateModal`（选文件 → 预览变更 → 统计表 → 名称确认 → 确认更新 / 回滚到更新前）。
- 更新后 `source.xlsx` 换成新模板（导出按新模板回填）；`id` / `is_active` / `accept_logs` / `photo_sync` 全不动。
