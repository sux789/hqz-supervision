## 「打开无反应」根因修复（20:27-20:45）⚠️ 重要教训
- 用户报 点击「打开」无效果。agent-browser 真实浏览器复现+eval 定位，两层根因：
  1. jsdelivr CDN 的 jspreadsheet.min.js 在用户浏览器加载失败（transferSize=0B，国内不稳定）→ jspreadsheet is not defined。
  2. 修复 CDN 后又暴露第二层：**jsuites 库会定义全局函数 BASE**（进制转换工具），把 v0.6 注入的 window.BASE='/supervision' 覆盖掉 → 所有 fetch URL 前缀变成函数字符串 → 404 → 点击无反应。此 bug 自 v0.6 起就存在，curl 冒烟测不出来，只有真实浏览器能抓到。
- 修复：①jspreadsheet/jsuites JS+CSS 全部自托管 static/vendor/（jsdelivr 对 jspreadsheet@4 下载不稳，npm pack jspreadsheet-ce@4.15.0 取 dist/index.js UMD 构建）②全局改名 window.BASE→window.SUP_BASE（4+5+1+1 处）③HTML 响应加 Cache-Control: no-cache（浏览器缓存旧 HTML 也会坑发版）。
- 验证：agent-browser 完整用户流——登录→点「打开」→#/wb/1 网格 1173 行渲染、13 列、可编辑列空白、工具栏 📷拍照/◎轨迹/相册/保存 全部就位（截图确认）。
- 教训：①前端全局名必须加业务前缀防库冲突 ②发版必测真实浏览器 ③CDN 依赖在国内产品里要自托管 ④no-cache 用于 HTML。
