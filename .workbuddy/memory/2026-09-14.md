## 修改密码 + 长期登录（08:46）
- 用户确认需求：本人改自己、管理员改他人、登录长期保存、**不影响别人（多人登录互不影响）**。
- 实现：①`POST /api/password`（本人，验原密码，返回**新令牌**本机免重登）②`GET /admin/api/users` + `POST /admin/api/users/<name>/password`（管理员重置他人，无需原密码）③`_TOKEN_DAYS` 180 → **3650（10 年）**④令牌增加**密码版本**：`users.pwd_ver`（迁移加列），改密码时 +1 → 该用户旧令牌失效；**旧格式令牌兼容**（rsplit 后长度 3 → 不校验版本），避免上线即全员登出。
- 前端：App 点右上角姓名 → 修改密码弹层（原/新/确认 + 三条校验：≥4 位、两次一致、不得与原密码相同）；后台「用户管理」卡片（列表 + 每行输入新密码 + 重置，带 confirm 提示）。
- **测试（本地 + 线上双跑）**：错误原密码 403；改密成功返回新令牌；旧令牌 401、新令牌 200；**他人令牌仍 200（关键）**；旧密码登录 401、新密码 200；普通用户访问 /admin/api/users 403；管理员重置他人 → 被改者 401、**其他人与管理員自己 200**；6 个账号密码最终复核全部 200（测试改动已恢复原值）。
- 界面实测（playwright）：弹窗三条校验 + 成功改密 + 令牌更新 ✓；线上后台用户管理 6 行（角色正确）✓。
- 「不影响别人」的技术口径：令牌按用户维度签名且带各自密码版本，**改密只失效该用户的令牌**；多人可同时在线（各自设备各自令牌）。

## v0.22 修复导出 + 注释后台两块（09:00）
- 用户反馈：前端导出 Excel 点击不起作用（猜不是按钮问题）；要求把后台「同步」「改密码」先注释掉。
- **导出根因（用户判断正确）**：导出接口本身正常（返回真正 xlsx 74KB，Content-Disposition 正确）；坏在**下载方式**——`window.open(URL,'_blank')` 在壳里被 MainActivity 的"一律留在 WebView 内"策略拦下，而 WebView 无下载能力 → 静默无反应。**修复**：改为 `fetch` 取 blob（带 X-Sup-Token）→ 原生 `saveFile`（mime xlsx，落「下载/验收导出」）→ 浏览器回退 `<a download>`；详情页与列表页两个入口统一走 `exportWorkbook(id, fallbackName)`。文件名优先取服务端 Content-Disposition（含中文+「导出」后缀）。
- **注释后台卡片**：`templates/admin.html` 把「云同步（照片 → 七牛暂存 → 百度网盘）」与「用户管理」两张 section 用 HTML 注释包起来（v0.22 标记），后端接口/数据/定时逻辑全部保留，删注释即恢复。**同步开关仍是开启**（照片照常上传网盘），仅隐藏界面。
- **连带修复（重要）**：卡片注释后 DOM 消失 → admin.js 里 `$('#btnSyncSave').addEventListener(...)` 之类会在 null 上报错、连带后续绑定失效；新增 `on(sel, ev, fn)`（元素存在才绑定）并把 3 处按钮绑定改用它，3 处加载调用加存在性守卫，3 个 load 函数首行加早退守卫。
