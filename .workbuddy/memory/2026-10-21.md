## v0.35 业务员可填的流程配置（doc/027，C26 / B28）

用户需求：一个流程多环节由业务员自定义；每环节显示哪些基本信息、提交什么（是否通过、不通过备注必填）；
巡视一对多多次、验苗一条记录对多小班、验收前后依赖；先出"用户填的文档"，再换成"业务员填的文档"；
业务员填完程序自动生成。

产出：
- `data/验收流程设计/流程配置-业务员填写版.xlsx` —— 5 张业务员表（①流程 5 条 / ②环节 26 个 / ③核验项 79 个 /
  ④选项 / ⑤字段字典）+ 填写说明；表头带批注、白名单列做了数据验证；预填内容按 2026-10-20 纪要改造。
  生成器 `tools/build_flow_doc.py`（可重跑，生成后自检必须 0 错误）。
- `flow_config.py`（新，B28）：解析+校验（错误带表名行号）+ 生成 {registry,flows}，与老 12 列格式同构。
- `tools/flow_build.py`：`--check / --emit / --apply <wid>`；apply 只改 workbooks.flows，先备份 sqlite。
- `main.py`：_parse_flows 优先识别业务员文档（source=user_doc）；_flow_hit 透传 subject/multi/
  basic_info/verdict/question/note_required/prev/need_result + 标准值按控件名映射；转序尊重 prev 且**必须通过**；
  必填支持控件自带 required；不通过原因服务端 400；flow_records 加 rec_no + GET 回传 multi。
- `static/flow.js` + `style.css`：基本信息条 / 是否通过双按钮 + 原因框 / 多次记录列表 / 数值对照判定 / 竖版。
- 测试：`tests/test_flow_config.py`（41）+ `tests/test_flow_e2e.py`（14）→ 全量 **292 项**。

坑与判断（下次别再踩）：
- `tools/run.sh` 会把 PY 覆盖成系统 python3（ai.sh 里 `PY="python3"` 是导出的），系统 python3 常缺 flask →
  回归闸报"0 通过 / 0 失败"，看着像没跑测试。已让 `tests/run_all.sh` 要求 openpyxl+flask 双依赖并自动回退。
- 业务员文档是独立文件（无 data 表），列名校验必须回退到 ⑤字段字典，否则 standalone 校验全跳过（等于没校验）。
- 老 12 列格式的「单行文本一律选填」不能直接改，会动线上流程；新格式走控件自带 `required` 才兼容。
- 照片张数业务员写「整地现场照片 2 张」（非「各 2 张」），parse_att 原来只认后者 → 下限恒为 0，已补。
- `独立入口` 流程在注册表里写 `条件字段=独立入口, 条件值=独立入口`，避免 cond_val 为空时
  `'' == ''` 被误判为无条件命中（match_flow 的真实坑）。

本地已验证：`--apply 466` 后 `/api/workbooks/466/flow` 返回 9 环节（人工造林 2026 版），

## v0.36 业务专家流程配置：入口维度 + 两级显隐 + 校验规则（doc/028）

用户第二轮四点：①改名「业务员」→「业务专家」（含文件名）；②问「行里选巡视/验收/材料，还是一个界面」；
③问「拆成 巡视/验收-人工造林/材料 三个文件是否更简化」；④明确专家要控制：显示哪些基本元素、
下拉里哪些不显示、提交什么控件、怎么验证、前置条件 —— 并问「能否理解，能否扩展」。

决策与产出：
- **不拆文件**（一个真相源），改「一个文件 + 入口列 + 界面入口 tab」。实测拆开是 3 文件 10/10/46 行，
  跨入口一致性（验收有的项目类型巡视有没有）拆开后必须另写脚本查。
- 流程唯一键 `flow_key(name, entry)` → `流程-{名称}·{入口}`；`GET/POST /flow` 加 `entry`，
  GET 回传 `entries`（含各入口环节数），flow.js 出 tab 由人切。
  **这是本轮发现的真问题**：验收/巡视同挂小班档案、同条件同优先级时 `match_flow` 只回一条，
  不加入口维度 **巡视永久不可达**。
- 两级显隐：②「显示的基本信息」白名单（**留空 = data 全部列**）+「不显示的基本信息」黑名单优先
  + ③「不显示选项」剪下拉。**必须下发 `expert` 标记**，否则老 12 列流程会突然冒出 29 列（线上崩）。
  列多时用原生 `<details>` 折叠（Chrome 73 支持）。
- 校验规则 DSL：`整数 / ≥0 / ≤100 / >0 / 10-100 / ≤500字 / 日期≥今天 / 正则:…`，`；` 分隔；
  配置期 `rule_ok` 认不出即报错；服务端 `check_rule`/`_rule_errors` 权威，前端 `ruleBad` 只做即时提示。
- 前置条件带结论：`整地=通过；回塘及底肥=合格` → `prev_result`；期望是正向词按 PASS_RESULTS 放宽判。
- 唯一性校验：`同小班同日唯一` / `同批次号唯一`。
- 规模：9 流程（验收4/巡视4/材料1）/ 25 环节 / 73 核验项。

**本轮 6 个坑（全踩过全修）**：
1. `re.split(r'[=＝]', item, maxsplit=1)` 只返 2 段，按 3 段解包 → ValueError。
2. `dict(AT, **{3: 'x'})` → `TypeError: keywords must be strings`，写 `{**AT, 3: 'x'}`。
3. 测试按 {流程名, 环节名} 定位行漏了入口 ——「日常巡护」在巡视入口，用验收入口找不到返回 0，
   `ws.cell(row=0)` 直接 ValueError。
4. 入口写错的真实文案是「在①流程里没有定义」而非「入口不认识」——**层级更高的错先报**，断言要贴真实文案。
5. **唯一性校验写死字段名**：原读 `记录日期`/`批次号`，而专家起的名字是「巡护日期」「进场批次号」→
   读不到值 → 退化成"今天"，等于随机拦/随机放。改为取**环节内第一个日期/批次控件**。
6. **换配置会吃掉老记录**：v0.35 的 `flow_sheet` 无入口后缀，v0.36 按新名查 → 一条读不到
   （现场表现"昨天填的全没了"）。`flow_build --apply` 现已自动迁移（无后缀→`·验收`，
   材料→`·材料`；只动本 wid、只动新配置里还存在的老名；`--dry-run` 先列出条数）。

回归：`bash tests/run_all.sh` = **338 项**（unit 108 + 流程配置 76 + e2e 109 + 流程 e2e 25 + exif 20），
七门 PASS。本地已 `--apply 466`（备份 `data/backups/app.sqlite3.bak_20261021_094656`），
实测默认入口 7 环节 / `?entry=巡视` 1 环节 / `entries=[('验收',7),('巡视',1)]`。

### 补充：Chrome 430px 截图自测又抓出 5 个真 UI bug（API 全绿 ≠ 界面对）
