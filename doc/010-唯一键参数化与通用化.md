## 一、需求

两个模板「同一套 App、不同的 Excel」暴露出多处硬编码，换个 Excel 就得改代码：

1. 数据 sheet 靠 `next(n for n in sheetnames if n != '参数')` 取"第一个非参数 sheet"——工作簿一带说明页/汇总页就**静默取错表**。
2. 行标识（照片归档、变更日志）硬编码 `headers.index('小班号')`，前端更有 **12 处** `rowVal('小班号')`。
3. 审计字段 `ACCEPT_LOG_FIELDS`、结果联动字段（前端写死 `验收人/验收日期/验收时间/验收备注`）、百分比列"列名含『强度』"的推断，都是写死的业务约定。
4. 拍照三件套（`相片备注`/`相片文件名`/`目录`）**恒必填**——一个纯填表、不拍照的 Excel 也得硬写三条拍照模板才能上传。

用户确认的口径：唯一键参数化、默认小班号；key 名**只认 `unique-key` 英文写法**；**未声明 = 不校验**；唯一键列**不做代码级只读**（靠参数配置）。

## 三、设计

### 3.1 新增 3 个参数 key（全部可选，缺省走内置默认）

| key | 类型 | 默认 | 语义 |
|---|---|---|---|
| `unique-key` | 文本 | （空；未声明则不校验） | 数据表中作为行唯一标识的列名。声明后该列**必须非空且唯一**，否则拒绝上传；且**不得出现在「可编辑列」**中 |
| `日志字段` | 列表 | 见 `DEFAULT_LOG_FIELDS` | ①写 `accept_logs` 要审计的列 ②前端「结果联动」要填/清的列（**前后端共用同一份，由后端下发**） |
| `百分比列` | 列表 | 列名含「强度」且不含 `%` | 存 0-1 小数、需展示为百分比的列 |

### 3.2 生效值助手（`param_parser.py`）

| 函数 | 作用 |
|---|---|
| `unique_key_of(cfg)` | 声明的唯一键列名；未声明返回 `''` |
| `row_key_column(cfg)` | **行标识列**：声明优先，否则回落 `小班号` |
| `log_fields_of(headers, cfg)` | 审计/联动列：声明优先，否则取内置 5 列中真实存在的 |
| `percent_cols_of(headers, cfg)` | 百分比列索引：声明优先，否则回落旧规则 |
| `check_unique_column(rows, headers, cfg)` | 唯一键非空+唯一校验，返回带 Excel 行号的错误串或 `None` |

### 3.3 数据 sheet 定位（`main.py::_pick_data_sheet`）

1. 精确取名为 `data` 的 sheet → 命中即用（**多余 sheet 可容忍**，说明页/字典页不影响）
2. 否则若有且仅有 1 个非「参数」sheet → 用它（旧模板 `中幼林抚育验收` 兼容）
3. 否则 → **明确报错**，列出全部 sheet 名

### 3.4 结果联动规则（前端，通用化）

- 结果列：按既有命名约定 `<列>选项` 自动定位（`resultOptKey()`，早已通用）
- 联动字段：`cur.log_fields`（后端按 `日志字段` 算好下发；老工作簿回落同一组默认列）
- 字段角色**按列名判**：名含 `人`/`员` → 填当前登录用户；含 `日期`（无则含 `时间`）→ 填今天
- 选空 → 除结果列外的联动字段全部清空

→ 换一套列名（如 `检查人/检查日期/检查结论`）只需在参数 sheet 写 `检查结论选项` + `日志字段`，**不改代码**。

### 3.5 必填 key 按需化

- **恒必填**：`可编辑列`、`功能`
- **按需必填**：`相片备注`/`相片文件名`/`目录` —— 仅当「功能」含 `拍照`/`视频` 时要求；不拍照的纯填表 Excel 不必写
- 报错信息会提示"若该模板不拍照，请把「功能」改为不含 拍照/视频"

## 八、本次一并修复的线上问题：「退出」把用户丢出应用

### 8.1 事件（2026-09-14 23:xx，用户报"何明星登录不上了"）

查线上访问日志还原全过程：

```
23:03:26  何明星手机(HONOR BKQ-AN20/Android16) 打开 /supervision/
23:03:27  GET /api/me → 401（显示登录框）
23:03:49  POST /api/login → 200 ✅ → /api/me 200 → /api/workbooks 200   ← 登录成功、进入列表
23:04:30  GET /api/workbooks/4 → 200                                    ← 正常在用
23:05:14  POST /api/logout → 200   ★ 他点了「退出」
23:05:14  GET /                       ← ★ 被丢到网关首页（不是 /supervision）
23:05:16  GET /forest/login           ← 掉进了另一个应用
23:05:21 ～ 23:06:50  连续 9 次 POST /forest/login（全部失败）  ← 拿监督验收的账号反复试
23:11:01  自行回到 /supervision → 23:11:06 登录成功
```

**当天所有 `POST /supervision/api/login` 全部 200**，登录从未失败过——问题不在账号密码，
而在**退出后的落点**。

### 8.2 根因

`static/app.js:129` 与 `static/admin.js:303` 的「退出」按钮硬编码 `location.href = '/'`。
`/` 是**网关首页（所有应用的入口）**，不是本应用。用户退出后被丢到网关首页，很容易点进别的
应用（forest），再用本应用的姓名/密码去登录那个应用 → 永远失败 → "登录不上"。

### 8.3 修复

```js
// 退出后必须留在本应用内；window.SUP_BASE 由 Flask 注入 = request.script_root
location.href = (window.SUP_BASE || '') + '/';
```

### 8.4 验证（线上，用何明星手机的同款 UA）

| 路径 | 退出后落点 | 结果 |
|---|---|---|
| App 主界面 `#btnLogout` | `https://forest.bibook.top/supervision/`（登录框可见、localStorage token 已清） | ✅ |
| 后台 `/supervision/admin` `#btnLogout` | `https://forest.bibook.top/supervision/`（登录框可见） | ✅ |

### 8.5 复盘教训

**"用户说登录不上" ≠ "登录接口坏了"。** 先看访问日志里**有没有失败的登录请求**：
本次一条 401 登录都没有 ⇒ 请求根本没到服务器 ⇒ 问题在客户端/落点，而非鉴权。
另外，**凡是跨应用共享域名的部署（gateway 多应用），跳转目标一律用 `SUP_BASE` 锚定本应用，
禁止硬编码 `'/'`。**
