# 052 - v0.52 迭代记录_材料核验（项目级按批次 + 多小班覆盖）

> 七段式。第 6 段反转记录不可省。

## 1. 需求背景（用户原话）

> 「材料核验，环节中可以增加 材料核验（比如苗木核验，有肥料核验），可以选有多个小班号 check box，
> 也可以上传 图片和文件，提交后对应小班不再提示 材料核验 了，材料核验 配置到参数或别的地方，
> 满足条件最小化改动和人性化操作」

四轮确认后的口径（用户拍板，不再讨论）：

| 岔路口 | 结论 |
|---|---|
| 覆盖判定粒度 | **按环节各自判定**：苗木验了、肥料没验 → 只提示肥料 |
| 不通过是否算完成 | **不算**，继续提示（能把不合格批次号带出来） |
| 配置位置 | **参数页一个 key**：`材料核验流程 = 流程-材料核验` |
| 提示落点 | **只在小班面板顶部一行**（不进后台进度列、不做行标色、没有单独导出块） |

## 2. 验证结果（改前数据对比/报错现场）

- 老格式（`flow_config/1`，本地 wb=466）**已经有**这套能力：「流程-材料检验（按批次）·材料」，
  2 环节都是 `关联小班=多选` + 上传按钮，`row_idx=-1` 项目级。
- 但**线上在用的 v2 模板没有**：wb=1191（蔡师版，149 小班）的
  `_tpl_hit` 首行就是 `if ridx is None or ridx < 0 … return None`，
  `STEP_COLS` 里也没有「关联小班」列 → 材料核验在 v2 上**根本进不去**。
- 改前实测：`GET /api/workbooks/<新上传>/flow?row=-1&entry=材料` → `ok:false`；
  前台 `#btnMaterial` 也因 `flows.registry` 不存在而不显示。
- 顺带发现：`parse_routes` 对「流程路由」做**表头全等校验**，所以「项目级」标记不能加列（会让全部现存模板报错）
  → 只能走参数页（这也是用户选参数页的技术理由）。

## 3. 设计方案（逻辑+口径依据，引用证据文件）

- **复用 `row_idx=-1` 哨兵**（C27 同源）：材料核验的记录与批次都在 `flow_records` 里 `row_idx=-1`，
  查询靠 `flow_sheet` 隔离，不加列、不改老记录语义。
- **项目级认定走参数页**：`材料核验流程` 一行；解析期把该路由标 `project=True`、强制 `repeat=True`、
  `independent=True`，并生成 `flows['material']={flow,key_col,no}`。
- **「关联小班」用环节页尾列**（不需要/单选/多选）：`_read_sheet` 对短表自动补空 → 老模板零改动；
  选了值就生成一个多选控件，选项在**命中时**才填（149 个班号不进 flows 快照）。
- **小班侧只做提示、不做流程**：`routes_for` 结果里过滤掉 `project` 路由，
  所以小班的流程下拉永远看不到材料核验（否则现场会在某个小班里填成单班记录），
  小班面板顶部改为一行状态：`材料核验：还差 1 项 ⚠ 肥料核验 未核验`。
- **覆盖判定只在服务端算**（`_tpl_material_status`）：取该工作簿 `row_idx=-1` 的全部记录，
  按 `rec_no` 归并；某环节覆盖该小班 = 该环节「关联小班」含此号 **且** 该次结论 ∈ PASS_RESULTS。
  不通过只记 `fail_batch`（界面显示「（M-002 不合格）」），不算完成。
- **批次号是整条流程的**（一批货一个号），所以标签取整条记录里第一个名字含「批次」的格子，
  不给每个环节各配一个批次号（人性化：现场只填一次）。
- **人性化三处**：①「关联小班」超过 20 项给筛选框（149 个班不靠手滚）；
  ②项目级面板隐藏顶部「项目类型/标段/乡/村/小班号」选择栏（430px 实测会误读成"只报当前班"），
  顶栏标题改「材料核验 · 模板名」；③勾的小班号服务端校验必须在本表内（手写错号会让覆盖永久失效）。

## 4. 代码修改（文件+行号+要点，不写全 diff）

- `param_parser.py`：`KEYS` 增 `材料核验流程`（文本）；值必须以 `流程-` 开头，否则带行号报错。
- `flow_tpl.py`：`STEP_COLS` 尾加 `关联小班` + `LINKS`；`parse_flow_sheet` 读该列 → `step['link']` +
  `_link_control()`；`material_of(config)`；`parse(..., material_flow=, key_col=)` → `_material_block()`
  标 `project/repeat/independent` 并回 `material` 块（配置不对只报 warn，不阻断上传）。
- `wb_parse.py`：`_parse_flows` 透传 `material_flow` 与 `row_key_column(config)`。
- `flow_hit.py`：`_tpl_hit` 首行分流 → `_tpl_project_hit`（常量列 + 关联小班选项 + flow_list 单条）；
  小班分支 `routes` 过滤 `project`；`_tpl_material_status / _as_keys / _batch_label / _rec_batch / _tpl_keys`。
- `main.py`：`/flow/batch` 增「小班号白名单」校验（400 带具体号）；`api_flow` 回 `material/project/project_key_col`；
  `_progress_flows` 跳过 `project` 路由（否则 149 行材料列全是"未填"）。
- `static/flow.js`：`materialHtml()` 状态行 + `renderV2` 插入；项目级 meta 文案；
  多选 >20 项出 `.fs-filter` 筛选框；项目级不显示选择栏/标题改写由 app.js 做。
- `static/app.js`：`wbHasMaterial` 兼容 `flows.material`；`openFlowView(idx<0)` 隐藏 `#selectorBar/#selMeta`、改 `#pageName`。
- `static/style.css`：`.flow-mat`（绿/橙两态）、`.mat-ok/.mat-miss`（整项换行，防「M-」「001）」断行）、`.fs-filter`。
- `templates/index.html`：按钮文案「🧱 材料核验」；静态资源 `?v=0.52.0`。
- 模板（两份都打，`.bak_20261106_material` 备份）：参数加一行、新增 `流程-材料核验`
  （进场批次号 / 苗木核验 / 肥料核验 / 备注 / 是否通过）、流程路由加一行（项目类型留空=公用，可重复，按批次）。

## 6. 反转记录（反转了哪条旧决策，为什么）

- **测试断言为什么改**：`T1` 原断言「路由 5 条」，模板真的多了一条 `流程-材料核验` → 改 6 条，
  不是放宽断言（同一条仍校验 `schema==flow_tpl/1`）；`T2b/T13d/T14` 的 5 条名单**没动**，
  因为小班/导出/进度三处都把材料核验排除了 —— 这三条正是本次的护栏，动它们才是掩盖回归。
- **main.py 不拆**：本次按「最小改动」口径只加一个校验块 + 三处过滤，拆积木与改行为不同版（C32 精神）。

- **反转 C27①「项目级只走老格式」**：v0.37 把 `row_idx=-1` 只做给 `flow_config/1`；
  现在线上跑的是 v2，材料核验在 v2 上完全不可用 —— 同一语义扩到 `flow_tpl/1`，
  老格式分支一行未动（`_tpl_hit` 与 `_project_hit` 并存）。
- **反转「材料核验必须配成一条独立流程」**：仍是流程（可复用控件/附件/审计），
  但**从小班下拉里摘掉**，只留工具栏入口；之前没有这条，是因为 v1 的材料流程注册条件
  `独立入口=独立入口` 天然匹配不到行，v2 没有这个字段，必须显式过滤。
- **反转「后台进度每个流程一列」**：材料核验在小班维度是"未填"噪音（149 行全灰），
  用户也确认提示只放小班面板 → 进度表两处（`_progress_flows`）显式跳过 `project`。
