# 038 - v0.46 迭代记录_卫星持续跟踪

## 1. 需求背景（用户原话）

> 轨迹不是持续记录，而是保持卫星跟踪，便于后续得到更准确的卫星位置。如果有提示，提示改为持续跟踪

口径拆解：

- **跟踪常开**：拿到定位权限就保持 `GPS_PROVIDER` 跟踪，让接收机星历/钟差保持热态；
  后续打卡、水印、拍照的一次性定位更快、更准。
- **记录仍手动**：轨迹点是否落缓冲/上传，仍由「▶ 记录轨迹 / ⏹ 结束轨迹」控制（v0.33 不变）。
- **提示改名**：常驻通知与页面提示从「轨迹持续记录」改为「卫星持续跟踪」。

## 2. 验证结果（改前数据对比/报错现场）

改前（v0.33–v0.45）跟踪与记录是一个开关：

- `BgLocationPlugin.ensureTrackingIfPermitted()` 里 `if (!trackOnPref()) return;`，
  不点记录按钮时 **GPS 监听根本不注册**；
- 打卡/水印走 Web `getCurrentPosition`，此时是冷启动 fix（林区首次 30s~几分钟），
  精度差且等待久——与「保持卫星跟踪」的诉求相反；
- 常驻通知标题为「轨迹持续记录中」，与用户要表达的「跟踪」语义不符。

证据：`android/.../BgLocationPlugin.java` 的 `ensureTrackingIfPermitted/onLocationChanged/updateNotificationThrottled`；
`android/.../BgLocationService.java` 的默认 title/channel。

## 3. 设计方案（逻辑+口径依据，引用证据文件）

1. **一件事拆成两件**：
   - **卫星跟踪**：只由定位权限决定。`load()` / `handleOnResume()` / `startWatcher()` /
     `setTracking(on)` 四处幂等自启（`ensureTrackingIfPermitted`），授权即注册监听 + 前台服务。
   - **记录开关**：`SharedPreferences track_on` 只决定 `onLocationChanged` 是否把点写入
     内存/CSV 并推给网页；关闭时监听继续、但不产生轨迹点。
2. **结束轨迹不再停跟踪**：`setTracking(false)` 只清开关并刷新通知，不再调用 `stopGps()`；
   只有权限被撤 / `stopWatcher()`（老页面兼容）才停跟踪。
3. **通知语义**（`BgLocationService`）：
   - 标题固定「卫星持续跟踪中」；
   - 空闲文案「仅 GPS · 保持卫星定位，后续打卡/拍照坐标更准」；
   - 记录中文案「仅 GPS · 保持卫星定位 · 记录轨迹中 · 已录 N 点」；
   - GPS 关闭「GPS 已关闭，卫星跟踪暂停（请打开系统定位）」。
4. **网页**：轨迹按钮语义不变（开始/结束记录）；toast 与按钮 title 改「卫星持续跟踪中」；
   打卡 `getCurrentPosition` 增加 `enableHighAccuracy: true`，直接复用热态卫星 fix。
5. **代价**：授权后前台服务与通知常驻，耗电高于 v0.33。这是用户明确选择的取舍
   （「保持卫星跟踪，便于后续得到更准确的卫星位置」）。

## 5. 测试验证（用例清单+一致率+断言项）

- `node --check static/app.js` / `node --check static/flow.js`：语法 PASS。
- `bash tests/run_all.sh`：419 项全绿（本轮未改 Python 侧）。
- `bash tools/run.sh`：七门 PASS。
- Java 无法本机编译（无 Android SDK）；推送后由 `android-build.yml`（paths 含 `android/**`）编译验证。
- 真机走查清单：
  1. 已授权冷启动 → 通知「卫星持续跟踪中」，不点记录按钮也有常驻通知；
  2. 不点记录 → 轨迹点数不增长（不产生 trajectory），打卡坐标 acc 明显改善；
  3. 点「▶ 记录轨迹」→ 点数上涨、通知出现「记录轨迹中 · 已录 N 点」；
  4. 点「⏹ 结束轨迹」上传成功 → 通知回到「保持卫星定位」，跟踪不停；
  5. 系统撤销定位权限 → 通知消失、跟踪停止；重新授权并回前台 → 自愈恢复。

## 6. 反转记录

- 反转 **v0.33「记录开关同时控制卫星采集启停」**：用户要求卫星跟踪常开以提升后续单点定位精度；
  记录（落点/上传）仍保持手动、按小班归属。
- 轨迹语义演进：v0.32「授权即持续采」→ v0.33「手动开始/结束记录」→ v0.46「跟踪常开 + 记录手动」。
- 通知语义反转：「轨迹持续记录中」→「卫星持续跟踪中」（跟随用户口径，不改业务能力）。

## 7. 部署记录

- 网页侧随 `./deploy.sh` 上线；原生侧需出包 **versionCode 12 / versionName 0.12**。
- 新网页 + 旧 APK（≤0.11）仍可用：旧 APK 只在记录时跟踪，提示文案可能仍是旧版。
- 首次升级后请确认系统未限制「监理验收」的后台定位权限（常驻跟踪依赖前台服务）。
