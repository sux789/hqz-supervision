# 026 · v0.34 AI 协作提速与多 Agent 并行

> 日期：2026-10-18 ｜ 类型：工程基建（不改业务行为）｜ 主文档：`doc/024-AI高效协作手册.md`
> 一句话：把「每次会话手工读 30KB + 手工跑 6 项检查 + 手工回想该跑哪些测试」压成**三条命令**，
> 并给「两个 Agent 同时改一个仓库」装上可机器判定的边界。

---

## 1 需求

1. **改动要高效**：一次改对，少来回。人给指令 → AI 定位 → 改 → 验证，全链路有坐标、有闸门。
2. **人容易对齐 AI 思路**：人 30 秒能回答「现在能不能提交 / 这版改了什么 / 红了先做什么」。
3. **最高性价比**：只投入能拧动「歧义度 / 影响面 / 反馈延迟」的事；照搬模板里用不上的门一律不接。
4. **越开发越简单**：知识沉淀成约束与断言，人工动作每版净减少，而不是越堆越乱。
5. **支持多 Agent 同时开发**：范围、所有权、合并顺序可机器判定，冲突在认领时就被拒绝。
6. **手册自身可成熟**：有版本、有反转、有冷静期、有减法节奏。

## 3 设计

**三旋钮**（`doc/024` §1）：返工成本 ≈（歧义度 × 影响面）÷ 反馈延迟。本次只做拧旋钮的事：

| 旋钮 | 交付 |
|---|---|
| 歧义度 | `brief`（4KB 现状）、`map`（符号→行号）、任务卡范围语法、DOD 表 |
| 影响面 | 文件级租约 + 行范围重叠判定；入口文件只许集成者改（C24） |
| 反馈延迟 | pre-commit 156ms / pre-push 全量 / `triage` 把红变待办 |

**三本账**（§2）：事实账（AI 可改）/ 判断账（人拍板）/ 过程账（机器生成，C23）。
**不做**：数据管线双跑对比（无输出目录）、常驻守护、自动改代码、覆盖率游戏。

## 5 测试（含建这套工具时抓到的真 bug）

首次跑闸门就抓到 3 个真问题（这就是"闸门不是摆设"的证据）：

1. `doc/001` 编号重复 → 门 3 FAIL（索引腐化，AI 引用会指错文件）。
2. `AI_INSTRUCTIONS` 残留 `[P0 客户 > …]` 占位符 → 门 4 FAIL。
3. 模板 FATAL 5 条 → 门 7 WARN（已知，记录不处理）。

建工具过程中修掉的自身 bug（都已回归）：

| bug | 症状 | 根因 | 修法 |
|---|---|---|---|
| `--json-only` 输出污染 | 下游 JSON 解析失败 | 进度行与 JSON 同流 | json 模式不打印人读行 |
| 任务卡冲突漏判 | 第二张重叠卡照样 active | `claim` 只比 active 两两，没把"待认领的"算进去 | `_against(task, active)` 单卡比对 |
| 路径首字符丢失 | `.gitignore` 显示为 `gitignore` | `git status --porcelain` 经 `strip()` 吃掉首行前导空格 | 直接 `sh()` 取原始输出 |
| pre-commit 提示误导 | `--no-write` 仍说"已写入" | 打印未区分落盘 | 文案按参数分支 |

## 6 反转与退役

- **反转 R-026-1**：模板的七门（validate / check_invariants / compare）**不启用**——本项目无输出目录，
  会永远 SKIP。回归等价物是 `tests/run_all.sh`（237 项）。**SKIP 的门不是防线，是噪音。**
- **反转 R-026-2**：`AGENTS.md` 从"按顺序必读 5 个文件"改为"先 brief，再按需回查"——
  必读清单本身是上下文成本，简报才是压缩后的入口。
- **退役**：五个从未接线的骨架下沉 `tools/legacy/`（保留可追溯，不进根目录）。
- **债务 D-026-1**：`explain` 的积木归属靠文件名精确匹配；文件改名未同步 BLOCKS 时显示"未登记"（不报错）。
- **债务 D-026-2**：`map.py` 的 JS 符号识别是正则近似，箭头函数赋值的匿名函数不会出现在地图里。
- **债务 D-026-3**：`brief` 的约束索引按前 30 字截断，长约束只能看 ID 回查（有意为之，避免挤爆预算）。

## 本版减掉的人工动作

1. 每会话手工读 6 个入口文件（约 30KB）→ 一条 `brief`（3.7KB）。
2. 手工记「这版该跑哪些检查」→ 一条 `run.sh`（七门）。
3. 手工回想「上次红的是什么、先查哪」→ `triage` 出处置顺序。
4. 手工判断「这次改动风险大不大」→ `explain` 按规则算风险等级。
5. 口头约定「你别改 main.py」→ 任务卡租约，重叠当场拒绝。
6. 提交信息习惯性不写 Refs → 钩子强制。
