## 一、项目定位与技术栈

通用 **Excel 网格填表工具**：上传多份 `.xlsx` → 选一个进入 → 手机上逐行填表、拍照/录像/记录 GPS 轨迹 → 按原模板格式导出 Excel，照片可选同步到百度网盘。

**不内置任何行业业务逻辑**（不做样地/GDB/调查业务）。所有行为差异由 Excel 里的「参数」sheet 驱动 —— 换一份列名不同的 Excel，理想情况下**不改代码**（C01/C11）。

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Flask（单文件 `main.py`，1584 行）+ SQLite | 41 个路由，Blueprint `bp`，挂载前缀 `/supervision` |
| 参数解析 | `param_parser.py`（468 行，纯函数） | 解析「参数」sheet → 校验 → 配置 dict；可独立测试 |
| 前端 | 原生 JS + jspreadsheet-ce@4 + jsuites | `static/app.js` 1758 行（App 端）/ `static/admin.js` 600 行（后台） |
| 云同步 | `sync_cloud.py`（579 行，**纯标准库**） | 服务器 shared_venv 没有 requests/qiniu，故手写七牛+百度 HTTP 调用 |
| 轨迹导出 | `track_export.py`（256 行，**纯标准库**） | 手写 shapefile（PolyLineZ + .shx/.dbf/.prj/.cpg） |
| 照片 EXIF | `static/photo_exif.js`（83 行）+ `static/vendor/piexif.js` | 依赖注入，浏览器/node 通用 |
| Android | Capacitor 6 远程 URL 壳 + 5 个 Java 原生类 | `top.bibook.supervision`，见 §七 |
| 部署 | gateway 进程内挂载（gunicorn:8090 + DispatcherMiddleware） | `./deploy.sh`，只 rsync 代码 + 重启 gateway，**不碰数据库** |

## 五、参数 Sheet 协议（本项目的核心设计）

### 5.1 结构
- 文件需含且仅需一个名为 **「参数」** 的 sheet，表头固定 6 列：`key | value | 类型 | 默认值 | 说明 | 示例`
- 数据 sheet 定位：优先精确取名 `data` 的 sheet；否则要求"有且仅有 1 个非「参数」sheet"，否则**明确报错**（禁止静默取第一个 —— 模板里带说明页会取错表）

### 5.2 全部 14 个 key

| key | 类型 | 必填 | 作用 |
|---|---|---|---|
| `可编辑列` | 列表 | **恒必填** | 允许编辑的列（其余只读） |
| `功能` | 列表 | **恒必填** | 开启哪些能力：`填表`/`拍照`/`视频`/`轨迹` |
| `相片备注` | 模板 | 功能含拍照/视频时必填 | 水印正文（**首行固定为时间戳，不参数化**，C06） |
| `相片文件名` | 模板 | 同上 | 照片文件名 |
| `目录` | 模板 | 同上 | 照片子目录 |
| `验收结果选项` | 列表 | 否 | 「验收结果」下拉候选（选"空白"=撤销验收） |
| `不显示列` | 列表 | 否 | 前端隐藏的列 |
| `搜索选项` | 控件映射 | 否 | `列\|控件` 形式决定列表页搜索控件 |
| `压缩最长边` | 数值 | 否 | 覆盖后台图片压缩默认（优先级：参数 > 后台 > 内置） |
| `压缩质量` | 数值 | 否 | 同上 |
| `unique-key` | 文本 | 否 | **行唯一标识列名**（只认这个英文写法）。声明后该列必须非空且唯一，违反→拒绝上传并报错带 Excel 行号；且不得出现在「可编辑列」 |
| `日志字段` | 列表 | 否 | 审计列，缺省 = 验收人/日期/时间/结果/备注 |
| `百分比列` | 列表 | 否 | 存 0-1 小数、需显示为百分比的列 |
| `导出筛选` | 控件映射 | 否 | 后台「下载 Excel」弹框字段声明，格式 `字段\|select` / `字段\|date`，**只筛行不筛列** |

### 5.3 语法约定
- 多值分隔 `;`，子字段分隔 `|`，目录 `/`，文件名段 `_`
- 占位符 `{{列名}}` / `{{sheet名称}}` / `{{时间}}`，**保留字**：`sheet名称` `时间` `拍照人` `工作簿id` `工作簿名` `工作簿文件名`（后三个 v0.29.3 加，用于把照片按工作簿分层）
- 全角分隔符（`｜；，`）自动归一
- **任何违规必须带 Excel 行号报错**，不许静默容错

## 八、前端功能清单

### App 端（`app.js`）

- **导出**：fetch 取流 → 原生 `saveFile` 落「下载/验收导出」→ 浏览器回退 `<a download>`

## 九、关键链路（接手后优先读这几段代码）

### 1. 拍照 → 上云全链路
```
App 拍照 → 原片 File
  ├─ photo_exif.exifOf(原片)  读 GPS/拍摄时间 → 水印坐标与时间（缺失退回 getCoords()/当前时间）
  ├─ Canvas: drawImage(摆正) → 画水印 → toBlob('image/jpeg', 压缩质量)
  ├─ photo_exif.preserveExif(原片, 压缩图)  回写 EXIF（Orientation 强制 1 / 删尺寸 / 删 MakerNote）
  ├─ 原生 savePhoto → Pictures/{目录}/{文件名}.jpg
  └─ 若 sync_enabled=1：POST /api/photo
        → 七牛 zz-1 暂存（state=received→qiniu_ok）
        → data/pending 落盘
        → 后台 daemon 推百度网盘 → state=baidu_ok
        → 成功后删 pending；七牛副本按 sync_keep_days(30 天) 清理
```
**排查"照片没同步"第一步永远先看 `sync_enabled`** —— 关闭时 App 拿到 `/api/sync/enabled=false` 就静默跳过，表现为 `/api/photo` 零请求、`photo_sync` 无新记录。

### 2. 远端路径拼接
```
app_dir + prefix + 目录模板渲染
默认 /apps/supervision/ + '' + {{工作簿id}}_{{工作簿名}}/{{小班号}}
  → /apps/supervision/123_造林项目-验收模板/YJ-515/xxx.jpg
```
`app_dir` 由百度应用 app_key 固定，**改配置前先确认**；v0.29.2 已做斜杠折叠（用户会填 `/apps/x/` 导致 `//`）。

### 3. 「更新 Excel」合并（`merge_rows()` 纯函数）
```
以既有行顺序为基准 → 匹配行原地合并（row_idx 不变，变更日志不错位）
新表多出的行追加末尾 / 旧表独有行保留不删
按列名对齐（列可增删换序），输出列序 = 新表列序，数值类型必须保留
冲突取值：只有「可编辑列」（旧∪新）旧值非空优先，其余列以新表为准
写库前自动备份 DB 行 + 源模板 → workbook_backups（每簿 5 份）→ 可 rollback
```

## 十、硬约束（改代码前必读 `CONSTRAINTS.md` 全文）

摘要，**违反 = 返工**：

| 编号 | 一句话 |
|---|---|
| C01/C02 | 业务行为一切由参数 sheet 驱动，禁硬编码；违规必须带 Excel 行号报错 |
| C03 | 不影响 hqz-survey / hqz-cam-app，独立 appId/路径 |
| C05 | 密码 sha256 存储，不明文进代码/日志；后台接口必须校验 admin |
| C06 | 水印首行时间戳**不参数化** |
| C07/C09 | 照片不在服务器长期存储；**视频永不上云** |
| C08 | 导出必须按源模板回填；静态 JS 改动必须提 `?v=` 版本号熔断缓存 |
| C10 | 图片压缩 / 视频压缩 / 云同步是三件独立的事 |
| C11 | 唯一键与通用化：行标识走参数，删工作簿连带清源模板与关联行 |
| C12 | **一切跳转/回退/下载地址必须用 `window.SUP_BASE` 锚定本应用**，禁硬编码 `/`（`'/'` 是网关首页，会把用户丢进别的应用） |
| C13 | 前端隐藏 ≠ 权限，边界只在服务端；**禁止用 URL 参数当权限开关**；不可逆操作必须照着名称确认，用自建弹层不用 `window.prompt`（Android WebView 不实现 `onJsPrompt`）；标志位为 0 时禁止写在 `or` 左侧 |
| C14 | 防抖保存必须能在离场前冲刷（四条路径）；待保存任务必须快照 wid/ridx/values；卸载用 `fetch(keepalive)` **禁用 `sendBeacon`**（带不了 `X-Sup-Token`）；`datetime` 判断必须先于 `date` |
| C15 | 「更新 Excel」保留原工作簿 id；以既有行顺序为基准合并；可编辑列旧值非空优先；不设重合比例闸门；必须可回滚 |
| C16 | 可能不存在的元素引用必须走 `on()` 或空值守卫，**禁止顶层裸 `addEventListener`**（否则整脚本加载失败、整页失效） |
| C17 | **不可假定第三方组件行为**：关键数据不依赖它派不派发事件，离场边界直接读 DOM；关键写入必须有落盘草稿；切后台先收值再冲刷；验证不得自证循环 |
| C18 | 用户打扰必须幂等：只做一次的引导要把"已做过"持久化到 localStorage（键名带版本号），禁只记内存变量 |
| C19 | 从 UI 读值回写：①优先官方 API（`getData()`），DOM 取值禁写死下标 ②必须有 sanity 闸（值==字段名即判读错）③读→自动保存链路必须先确认读源正确 ④验证用临时数据 ⑤审计日志记 `old_value` |
| C20 | EXIF 回写：Orientation 强制 1、删尺寸标签、删 MakerNote；任何失败静默退回原行为 |

### 写测试的三条硬规矩
1. **多身份必须各用独立 `test_client`** —— `auth_user()` 优先读 session，同一 client 先后登录会互相覆盖（表现为"管理员被判 403"）
2. **不要写死模板文件名与期望结果** —— 从 `data/*.xlsx` 自动发现，期望从文件内容独立推断
3. **每套用例用与自家表头匹配的参数基底** —— 拿别人的常量配另一套表头会先被"占位符不是表头"拦下，测不到目标分支
