# 037 - v0.45 迭代记录_通过判断

## 1. 需求背景（用户原话）

> 环节在添加一项通过判断，默认选正确通过，但是有些是数值，比如株数大于等于设置就为正确，
> 比如百分比大于多少为正确；帮我做性价比高的优化，比如代码最好根据excel 改变实现逻辑改变不修改代码，
> 比如优化文件符合 AI 开发高效不易错

三条口径：

- **默认显示「正确」**：实测没填之前不吓人，填了再实时重判。
- **规则来自 Excel**：株数/百分比/自动值的阈值写在模板控件列里，业务改模板即改行为。
- **结构面向 AI**：语法解析只留一份纯函数模块，前后端不各写一套；模板工具能回读校验。

## 2. 验证结果（改前数据对比/报错现场）

改前 `流程-整地` 第 6 环节「核实总株数」是普通数值输入：设计值 6076 株，实测填 6000
也照样能点「通过」；`流程-完工验收` 的「栽植成活率」「样地调查成活率」同理，
85% 的验收线只存在于人的记忆里，App 不做任何提示。服务端只校验 `≥0` 这类形态规则。

## 3. 设计方案（逻辑+口径依据，引用证据文件）

1. **复用控件 DSL，只加一个 `→规则`**：数值类控件写成
   `数值(株→≥设计值)` / `百分数(0-100→≥85)` / `自动(公式→≥85)`，
   与 v0.44 的 `→备注≥2` 同一位置、同一解析心智（`flow_tpl.parse_dsl` 的 `→` 约定）。
   不写 `→` = 不判断，老模板零变化（C28）。
2. **规则语法只有一行**：`(≥|>|≤|<|=) (设计值|数字) [×系数 | ±偏移]`。
   生产上先只用到 `≥设计值`、`≥设计值×0.95`、`≥85` 三种；系数/偏移留给验收细则变化，
   不加新控件类型。看不懂的规则在**模板解析期**报错（带表名+行号），不上线后才暴露。
3. **判定只实现一份**（`flow_judge.py`）：`parse → threshold → evaluate`，
   `fields()` 把结果拆成 `judge/judge_op/judge_ref/judge_value/judge_factor/judge_delta`
   随控件下发。**前端只做算术**，不复制正则；改语法只改一个文件。
4. **服务端权威**（C13）：提交「通过」前逐项判定，失败 400 并说明
   `实测 6000 不满足「≥ 6076」；规则 ≥设计值`。
5. **不把人堵死**：判定失败只拦「通过」；现场确实不达标时可选「不通过」+ 流程备注
   （v0.44 的备注闸门照常生效），记录与日志仍留痕。
6. **设计值缺失 = 判不了**：模板写了 `≥设计值` 但该小班设计列为空/常量时，
   提交「通过」会被拦下并说明「设计值缺失，无法判定」，而不是默认放过。
7. **AI 可维护**：新增 `python3 tools/tpl/tpl_tool.py doc --file …` 只重生成「说明」页
   （保留手工参数与数据），DSL 文档跟代码同源；模板回读 `show` 同时校验规则语法与设计列引用。

## 4. 代码修改（文件+行号+要点，不写全 diff）

- `flow_judge.py`（新增，B32）：`parse`（正则+归一 `>=`→`≥`）、`threshold`（设计值/系数/偏移）、
  `evaluate`（返回 `(True|False|None, 说明)`）、`evaluate_control`（读控件 `judge_*` 字段）、`fmt`。
- `flow_tpl.py`：`_split_judge` 切 `参数→规则`；`_judge_fields` 校验并落字段；
  数值/百分数/自动三个分支接入；`_note_control` 与控件基座补空字段（结构统一）。
- `main.py`：缺项校验后新增 `judge_bad` 循环——只对结论不是「不通过」的提交判定，
  失败合并且返回 400，文案带实测/阈值/规则与「现场特殊请选不通过」出口。
- `static/flow.js`：
  - `v2JudgeOf` 默认「正确（待填实测）」，填值后按 `judge_*` 算术，拿不到设计值给「无法判定」；
  - `v2JudgeHtml/refreshV2Judge` 只替换该条判断的 DOM（输入时不丢焦点）；
  - `v2JudgeFails` 并入底部缺项与提交前拦截（字段名与环节重名时不重复显示）；
  - 数值/自动控件就地渲染判断条。
- `static/style.css`：`.fs-judge` 四态（默认绿 / 待填灰 / 无法判定黄 / 不达标红）。
- `tools/tpl/tpl_tool.py`：`with_judge` 给有设计值的数值控件自动补 `→≥设计值`；
  `show_workbook` 校验规则语法并提示「引用设计值但设计列缺失」；新增 `doc` 子命令重生成说明页。
- `data/tpl-人工造林-验收流程模板.xlsx`：13 个控件写规则（整地 1、栽植 5、完工 7，含
  `百分数(0-100→≥85)` 与 `自动(...→≥85)`），备注列同步「通过判断：…」；说明页升 v2.7。
- `templates/index.html`：静态资源 `?v=0.44.0 → 0.45.0`。
- `deploy.sh`：同步清单加 `flow_judge.py`（C32②）。
- `BLOCKS.md`：登记 B32；`doc/037` 为本记录。

## 6. 反转记录（反转了哪条旧决策，为什么；无则写「无」）

- 反转「数值只做形态校验（≥0）」：验收细则里的「设计株数」「成活率 85%」是业务硬线，
  以前只能靠人看，现在由模板声明、App 判定。
- 保留「人不被堵死」：判定失败只拦「通过」，反转了「凡是校验失败都不许提交」的直觉；
  理由是现场客观条件可能让实测低于设计（如补植未完成），必须留下「不通过+说明」的真实记录。
- 未反转「备注只有模板声明才出现」：判定条不自动生成备注框，仍由 `→备注≥N` 控制（C33）。
