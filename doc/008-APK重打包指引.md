# 008 - APK 重打包指引（v0.11：视频本地保存与录音权限）

> 触发原因：视频改为「只存手机本机」后，需要原生侧新增两个能力——
> ① 视频写入**与照片完全相同的目录**（相册 `Pictures/{参数目录}/`，文件名加 `_视频`）；
> ② 录制**带声音**（原 APK 未声明录音权限）。
> App 是「远程 URL 壳」模式，页面代码改完即时生效；**只有原生能力需要重打包**。

## 1. 本次原生改动（已完成，待打包）

| 文件 | 改动 |
|---|---|
| `android/app/src/main/AndroidManifest.xml` | 新增 `RECORD_AUDIO`、`MODIFY_AUDIO_SETTINGS` 权限；新增 `<uses-feature android:name="android.hardware.microphone" android:required="false"/>` |
| `AppPermissionsPlugin.java` | ① 新增 `@Permission(alias="microphone", strings={RECORD_AUDIO, MODIFY_AUDIO_SETTINGS})`；② 新增方法 **`ensureMedia()`**（一次性申请相机+麦克风，返回 `{camera, microphone, granted}`）；③ 新增方法 **`saveVideo({base64,name,subdir,base})`**，默认写入 `Pictures/{subdir}/`（`base` 可改为 `Movies` 等）；④ `saveFile` 补 `.mp4/.webm/.mov` 的 mime 映射 |

**权限为什么不用自己写弹窗处理**：Capacitor 6 的 `BridgeWebChromeClient` 已内置 WebView 权限桥——
`VIDEO_CAPTURE → CAMERA`、`AUDIO_CAPTURE → RECORD_AUDIO + MODIFY_AUDIO_SETTINGS`，会走系统权限申请并在授权后 `request.grant(...)`。
所以**只需在 Manifest 声明权限**，页面里的 `getUserMedia({video, audio})` 就能拿到带声音的流；`ensureMedia()` 只是把"申请时机"提前到录制前，避免录到一半才弹窗。

前端调用链（已实现，v0.11.1）：
```
点🎬视频 → ensureMedia()（相机+麦克风一次申请）
          ├─ 相机被拒 → 提示 + 跳系统设置，录音中止
          └─ 麦克风被拒 → 静默降级「无声」录制（视频照常可拍）
→ getUserMedia(video+audio) → MediaRecorder 边录边压 → 停止
→ saveVideo({subdir}) → 相册 Pictures/{参数目录}/xxx_视频.mp4
   （失败回退 saveFile → 下载目录；再失败回退浏览器下载）
```

## 2. 打包方式（推荐用 CI，本地不必装 SDK）

### 方式 A：GitHub Actions 自动打包（最方便，已配置）
`.github/workflows/android-build.yml` 已配置：**推送到 `main` 只要动到 `android/**`（或 `www/**`、`package.json`、`capacitor.config.json`）就自动出包**，也可在 Actions 页面手动 `workflow_dispatch`。
1. `git push`（本次改动已含 `android/**`，推送即触发）
2. 打开仓库 → **Actions** → 最近一次 `Android APK` 运行
3. 页面底部 **Artifacts** 下载 `app-debug.apk`（或 workflow 中命名的产物）
4. 手机安装（Debug 包需允许"安装未知来源应用"；与已装应用**同签名**才能覆盖安装——见下方注意）

> 注意：Debug 包用 Android 默认调试签名，**与线上正式包签名不同**，直接安装会提示"签名冲突"，需要先卸载旧版（会清 App 本地数据，但照片/视频在系统相册不受影响）。若要能覆盖升级，走方式 B 的签名版。

### 方式 B：签名正式版（可覆盖升级）
1. 仓库 Secrets 配置四个值（脚本 `set_gh_secrets.sh` 已备好）：`KEYSTORE_BASE64` / `KEY_ALIAS` / `KEYSTORE_PASSWORD` / `KEY_PASSWORD`
2. 打 tag 或手动触发 `release.yml` → 产出签名 APK
3. 与线上包同签名 → 可直接覆盖安装，App 数据保留

### 方式 C：本机构建（需 Android SDK）
```bash
npm install
npx cap sync android
cd android && ./gradlew assembleDebug     # 产物：android/app/build/outputs/apk/debug/app-debug.apk
# 签名版：./gradlew assembleRelease（需 android/keystore.properties）
```

## 2.5 录制方式（后台可切换，v0.13）

| 方式 | 容器 | 体积 | 适用 |
|---|---|---|---|
| **`system`（默认）** | 系统相机录 → **MP4/H.264** | 较大（相机码率） | **兼容性优先**：任何相册/播放器都能播（华为等只有 WebM 的机型必须用它） |
| `inapp` | 页面 MediaRecorder → 优先 MP4；本机不支持则 WebM | 小（按后台码率压缩） | 省流量优先，但**部分机型（如华为 P40 Pro+）只能出 WebM，相册常提示无法播放** |

切换位置：后台「同步设置 → 视频」→「录制方式」。前端每次点击都实时读取该设置，**改完立即生效，无需刷新**。
`inapp` 模式下若实际录出 WebM，页面会红字提示并**自动引导系统相机重录**（MP4 保证可播）。

## 2.6 v0.13.2：原生录像 + 会话持久（本次新增）

| 改动 | 原因与效果 |
|---|---|
| 插件新增 **`recordVideo({name,subdir,maxSeconds,quality})`** | 用 `startActivityForResult` 调系统相机录像，回调里**流式复制**（256KB 缓冲）到 `Pictures/{subdir}/{name}`。**不再走 WebView 的 `<input capture>` 文件回传**——实测"录完点确认，App 弹登录页"就是因为系统相机顶掉 WebView、会话级 cookie 丢失 + 文件结果丢失；走原生会话则两者都不会发生，容器是相机原生 **MP4/H.264** |
| 服务端会话改 **30 天持久 cookie** | `permanent_session_lifetime=30天` + `session.permanent=True`（生产加 `Secure`+`Lax`）。系统相机/相册等外部 Activity 顶掉 WebView 后，页面重载不再要求重新登录 |
| 前端 401 提示 | 会话真过期时明确提示「登录已过期，请重新登录」，不再静默跳登录页；登录后 URL hash 仍在，会自动回到原小班 |

## 2.7 v0.14：原生录像**压缩**（像拍照一样带参数）

| 项 | 说明 |
|---|---|
| 目标 | 录像后按后台参数压缩：**分辨率** ≤ `video_max_height`（默认 720）、**码率** ≤ `video_maxrate_k`（默认 2500 kbps）、**保留声音**（AAC），输出 **MP4/H.264** |
| 实现 | `androidx.media3:media3-transformer` 转码（`Transformer` + `ScaleAndRotateTransformation` 缩放 + `VideoEncoderSettings.setBitrate` 控码率），临时文件 → 流式复制进 `Pictures/{subdir}/{name}` |
| 目录/文件名 | **与拍照完全一致**：`Pictures/{参数目录}/{相片文件名模板}_视频.mp4` |
| 开关 | 后台「视频」→「录制后原生压缩」`1/0`（默认开）；**转码失败自动回退保存原片**，绝不丢视频 |
| 进度提示 | 插件 `notifyListeners('videoStage')` → 前端提示「正在压缩视频…」/「压缩失败，已保存原始视频」 |
| 录制阶段 | `EXTRA_VIDEO_QUALITY=0`（相机较低码率录制，转码前体积已减半） |
| 代价 | APK 体积 +约 2.8MB（7.3MB）；转码耗时约为视频时长的 30-80%（后台线程，页面不卡） |

> API 适配记录：media3 1.4.1 的码率控制在 `DefaultEncoderFactory.Builder#setRequestedVideoEncoderSettings(VideoEncoderSettings)`；
> `Effects` 构造为 `(audioProcessors, videoEffects)`——两处均按 aar 内类签名核对后修正（首次 CI 编译报错 → 修正 → 通过）。

## 3. 安装后验证清单

| # | 操作 | 预期 |
|---|---|---|
| 1 | 小班详情 → 点「🎬 视频」 | 首次弹「相机 + 麦克风」授权（一次弹窗）；授权后进入全屏录制 |
| 2 | 录制界面顶部 | 显示 `720p · 2.5 Mbps · **有声** · 只存手机` |
| 3 | 录像 5 秒 → 点相机"确认/√" | 提示「正在压缩视频…」→ 随后「视频已保存：Pictures/{参数目录}/xxx_视频.mp4」，**不出现登录页** |
| 3b | 对比体积 | 压缩后文件明显小于相机原片（720p/2.5Mbps 约 1.1MB/5秒）；相册可正常播放且有声音 |
| 4 | 打开手机文件管理器/相册 | 视频与照片**在同一个文件夹**（`Pictures/{参数目录}/`），文件名含 `_视频` |
| 5 | 播放该视频 | 有声音 |
| 6 | 拒绝麦克风权限后重录 | 顶部显示「无声」，视频仍可正常录制保存 |
| 7 | 拒绝相机权限 | 提示去系统设置，不进入录制 |

## 4. 备注

- 服务器端 `/api/video` 与「视频压缩」设置项**保留但休眠**（前端不再调用）：将来若要做"视频也上云"，把上传逻辑接回即可，压缩参数已就绪。
- 视频**不入七牛/百度**，服务器零副本（C09）。
- Android 10+ 写系统相册走 `MediaStore`（自有媒体免存储权限），无需 `WRITE_EXTERNAL_STORAGE`。
