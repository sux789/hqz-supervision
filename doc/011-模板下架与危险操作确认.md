# 011-模板下架（软删除）与危险操作确认（v0.24）

> 版本：v0.24 ｜ 日期：2026-09-14 ｜ 状态：已实现并本地实测通过
> 关联约束：**C13（新增）**、C12、C08

## 一、需求与判断

用户提出两个设想：

1. 加「隐藏 / 显示」能力，默认显示，**只让前端看不见**；
2. 删除按钮加特殊参数才出现，例如 `admin?showdel=1` 才显示删除。

**结论（先说判断，再动手）**：

> 「隐藏＝只让前端看不见」这个**定位是对的**，但**用 URL 参数当开关不合理**。

理由（三条）：

| # | 问题 | 说明 |
|---|---|---|
| 1 | **会失效** | URL 参数最容易被记住并复用——谁把带 `?showdel=1` 的地址存一次书签，之后就永远开着。防误点的开关一旦常开，等于没有 |
| 2 | **会扩散** | URL 会进浏览器历史、会被复制粘贴、会被口头传播（"你开 `admin?showdel=1` 删一下"）。删模板这种不可逆操作，不该有一个能被顺手传出去的隐藏入口 |
| 3 | **会误导后来人** | 把"可见性"和"权限"揉进同一个参数，最危险的后果是下一个维护者以为加了参数就有了删除权限，于是在别处放松服务端校验 —— 典型的假安全 |

另外 URL 参数会**粘在地址栏**，同一标签页后续跳转都带着它，行为不可预期。

**关键事实**：删除接口本来就是服务端管理员校验（`main.py::admin_required` → 未登录 401 / 非管理员 403），按钮显不显示与安全**毫无关系**。所以这个需求本质是「**防误点**」，不是「**权限**」。

最终采用的分层方案（用户确认）：

| 层 | 目的 | 实现 |
|---|---|---|
| ① 安全边界 | 只有管理员能删 | **保持**：服务端 `@admin_required` |
| ② 防误点 | 别手滑删掉模板 | 危险操作前**要求照着输入模板名**；删除按钮不再是红色实心裸放 |
| ③ 可恢复 | 删错了能救回来 | **软删除（下架）**：默认隐藏于 App 端，数据全保留，可「恢复」 |

## 二、语义定义（C13）

**下架 = App/user 端看不见、不能操作；数据行 / 源 Excel / 变更日志 / 照片同步记录全部保留。**

- 「下架」是**软删除**，不是权限。用户端的按钮是否显示与它无关。
- 管理员**始终放行**（仍可在后台查看、下载已下架模板），便于维护与恢复。
- 彻底删除（不可恢复）**只放在已下架列表里**，且同样要求输入名称确认。

## 四、设计

| `init_db` | `workbooks` 加 `is_active`；轻量迁移 `ALTER TABLE ... DEFAULT 1` |

### 4.3 不用 `window.prompt` 的原因

危险操作确认**刻意用自建 DOM 弹层**：Android WebView 默认不实现 `onJsPrompt`，`window.prompt()` 在手机上会直接返回 `null` —— 那意味着**手机上永远确认不了**（功能形同不可用）。自建弹层在桌面与手机行为一致。

## 六、实现中踩到的坑（务必记住）

1. **`x or 默认值` 的经典陷阱**：`_inactive_for` 初版写成
   `if not r or int(r['a'] or 1) == 1: return False` —— 当 `is_active=0` 时
   `0 or 1` 得到 `1`，守卫**永远认为工作簿在用**，下架后普通用户照样能读能写。
   正确写法：`if r['a'] is None or int(r['a']) == 1: return False`。
   **教训：用 0 表示"关闭"的标志位，绝不能出现在 `or` 的左边。**

2. **Flask `test_client` 共享 cookie**：`auth_user()` 优先读 `session`（`X-Sup-Token` 只是后备），
   同一个 client 先后登录管理员与普通用户，会让后登录者的 session 覆盖前者 ——
   表现为"管理员请求被判成普通用户（403）"。**测多身份必须各用独立 client。**

3. 合成测试数据要"先填满再制造异常"：验证唯一键重复时，若新列只给两行赋值、
   其余行为空，会先被"**为空**"拦下而测不到"重复"分支。

## 七、反转

- 反转 v0.23「DELETE = 物理删除」→ 现为「DELETE = 下架（软删除），`?purge=1` 才物理删除」。
- 反转 v0.23「唯一键重复即拒绝上传」不变；但**已下架模板在 user 端一律 403**，这也顺带避免了
  用户在下架期间继续填写后与恢复后的状态冲突。
