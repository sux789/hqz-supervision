# 003-项目定位修正与通用网格填表设计

> 版本：v0.2 ｜ 日期：2026-09-11 ｜ 来源：用户定位修正指令（16:40）｜ 反转：doc/002 部分「迁移」叙事

## 一、需求（定位修正）

hqz-supervision **不是 hqz-survey 的调查功能复制品**，而是一个**通用的 Excel 网格填表工具**：

1. **通用性**：无样地、无 GDB 矢量、无调查专属业务。任何业务行为（可编辑列/选项/拍照命名/目录/搜索）都由「参数」sheet 驱动，换一个 Excel 换一套行为
2. **多工作簿**：后续支持上传多个 Excel，列表选择进入；不绑死某个文件
3. **先本地预览**：本地跑起来看效果，**暂不部署、不影响线上**（hqz-survey 线上业务照常）
4. **不重复**：独立 appId/名称/路径（参照 hqz-cam-app 衍生经验），与 hqz-survey、hqz-cam-app 三者互不干扰
5. **技术复用**：复用 hqz-survey 验证过的 excel js（前端网格 **jspreadsheet-ce@4 + jsuites**，CDN）和基础交互（拍照/轨迹按钮、搜索、toast 等），**不复用**其后端业务接口与 GDB/样地逻辑

## 二、验证

- hqz-survey 前端网格实为 jspreadsheet-ce@4（`survey/user/templates/base.html` L26-27 CDN 引入，app.js L1327 `jspreadsheet(...)` 实例化），非 SheetJS——本设计沿用同款
- hqz-survey 后端 Excel 为 openpyxl（exporter.py L33）；通用工具 MVP 走纯前端，后端导出待 B4 后再定

## 三、设计

### 3.1 架构：纯前端、零后端起步

```
上传 xlsx ──SheetJS 解析──> {数据 sheet, 参数 sheet}
        │
        ▼
  IndexedDB 工作簿库（多 Excel 存储，本地）
        │  列表选择
        ▼
  param_parser 解析参数 ──> AppConfig
        │
        ▼
  jspreadsheet-ce 渲染网格（可编辑列/不显示列/验收结果选项/搜索选项 驱动）
        │
        ├── 拍照：相机 API + 相片文件名/目录/相片备注 模板 → 相册
        └── 轨迹：GPS 记录 → GPX 导出
```

- **SheetJS（xlsx.js）** 负责浏览器端解析 .xlsx（hqz-survey 不需要它是因为数据走后端导入；通用工具的"上传即用"必须前端解析）
- **IndexedDB** 存多个工作簿（工作簿名+上传时间+各 sheet 数据），刷新/离线不丢
- 零后端 ⇒ 部署面为零 ⇒ 天然不影响线上其他业务；将来要管理端/服务端导出再加（B4）

### 3.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 网格 | jspreadsheet-ce@4 + jsuites@5（CDN） | hqz-survey 同款，交互/列类型/下拉验证开箱即用 |
| xlsx 解析 | SheetJS CE（CDN） | 浏览器端读 xlsx 的事实标准 |
| 存储 | IndexedDB（无框架原生 API） | 多工作簿持久化，离线可用 |
| 页面 | 单 HTML + app.js + style.css（PWA 可后续加 manifest） | 与 hqz-survey 结构同源，轻量 |

### 3.3 页面流

1. **工作簿列表页**：上传按钮（可多选）→ 已上传工作簿卡片（名称/sheet 数/上传时间）→ 点击进入
2. **网格填表页**：顶部搜索栏（按 搜索选项 渲染 select/search）→ jspreadsheet 网格（可编辑列可编辑、不显示列隐藏、验收结果选项做下拉）→ 底部功能按钮（按 功能 键：拍照/轨迹）

### 3.4 迁移批次（修订 doc/002 §3.4）

1. **B1（本次）**：本地预览 MVP——上传+列表选择+参数解析+jspreadsheet 渲染（纯前端静态页）
2. **B2**：拍照（SheetJS 无关，走相机 API + 模板命名，对齐 doc/001 D1-D6）
3. **B3**：轨迹记录 + GPX 导出
4. **B4**：服务端能力（管理端、Excel 导出）视需要后定；届时再定独立 appId 与部署路径
