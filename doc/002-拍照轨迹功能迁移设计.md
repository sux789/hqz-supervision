# 002-拍照轨迹功能迁移设计（hqz-survey → hqz-supervision）

> 版本：v0.1 ｜ 日期：2026-09-11 ｜ 关联：doc/001、CONSTRAINTS.md C01/C02

## 一、需求

把 hqz-survey 的拍照、轨迹两大功能迁入本项目。迁移前提：hqz-survey 中这些行为**硬编码在前端 app.js**，本项目要求全部改为「参数」sheet 配置驱动。

## 二、验证（hqz-survey 现状调研，2026-09-11）

| 行为 | hqz-survey 实现 | 位置 | 问题 |
|---|---|---|---|
| 照片文件名 | `分类_乡镇_村_小班[_样地N]_时间戳.扩展名` | `survey/user/static/app.js` `buildPhotoName()`（约 L3033） | 段顺序与连接符硬编码 |
| 照片子目录 | `Pictures/{年度}年度/{分类}/{小班号}号调查小班/` | 同上 `photoSaveSubdir()`（约 L3005） | 层级、后缀文本硬编码 |

## 三、设计

### 3.1 对齐方案：参数 → 程序

```
「参数」sheet ──解析器(param_parser)──> AppConfig
                                          │
   数据 sheet ──网格渲染──> 填表页面 <────┤
                                          │
   拍照：相片文件名+目录+相片备注 → buildPhotoName/photoSaveSubdir/watermark
   轨迹：功能 含「轨迹」→ 显示轨迹按钮/记录/GPX 导出；不含则隐藏
```

### 3.2 程序功能改动决策（本轮自行决定项）

| # | 决策 | 依据 |
|---|---|---|
| D1 | **新增 `相片文件名` 键**（原表没有，hqz-survey 也硬编码） | 把 buildPhotoName 的段拼接配置化，参数表达才算闭环「优雅」 |
| D2 | 目录模板允许「文本+占位符混排」段（如 `{{小班号}}号调查小班`） | 兼容 hqz-survey 目录命名习惯，迁移零信息损失 |
| D3 | 照片根目录不进参数表，仍为部署常量（Pictures/Download） | 属设备侧约定，非业务配置；避免参数表膨胀 |
| D4 | 轨迹 GPX 导出逻辑原样迁移，仅入口受「功能」键开关控制 | 轨迹无历史配置可参数化，保留 hqz-survey 行为 |
| D5 | `验收结果选项/可编辑列/不显示列/搜索选项` 由新解析器消费，hqz-survey 无对应代码，按 doc/001 新写 | 全新增量 |
| D6 | 水印备注按 `相片备注` 模板渲染（`{{列名}}` 替换当前行值，`{{sheet名称}}` 替换 sheet 名），渲染失败该段留空并 WARN 汇总 | 水印属展示层，坏占位符不应炸掉拍照主流程 |

### 3.3 新项目积木拆分（MVP 后细化）

- `param_parser`：读参数 sheet → AppConfig（校验：未知 key/全角分隔符/占位符列名不匹配 → 带行号报错）
- `grid_render`：数据 sheet → 网格填表页（受 可编辑列/不显示列/搜索选项/验收结果选项 控制）
- `photo_mgr`：拍照/重编码 JPEG/水印/相册保存（文件名与目录由 AppConfig 驱动）
- `track_mgr`：小班轨迹记录 + GPX 导出（照搬 hqz-survey 交互：切换小班自动停存）

### 3.4 迁移批次

1. **B1（MVP）**：param_parser + grid_render，单文件 main.py 端到端跑通，`make_baseline.sh` 存基线
2. **B2**：photo_mgr（参数化命名/目录/水印）
3. **B3**：track_mgr + GPX 导出
4. **B4**：管理端/导出 Excel 视需要后定
