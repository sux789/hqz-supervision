# 016-事故复盘：v0.28 把「字段名」写成了值（v0.28.2 修复）

> 日期：2026-09-17 ｜ 影响版本：**v0.28 / v0.28.1**（10:44–11:13 期间在线）｜ 修复版本：**v0.28.2**
> 关联约束：**C19（新增）**、C17、C13

## 一、一句话

v0.28 为修"编辑丢失"而新增的 `syncGridIntoAllRows()` **读错了 DOM 列位置**，
把**字段名（label）当成字段值**写回内存并落库 —— 用户看到的正是
"已经填了的值，重新加载后，验收相关前端显示，值变为 label 了"。

## 二、根因（实测，不是推断）

jspreadsheet 渲染的每行是 **3 个格子**，不是 2 个：

```
tr.children[0] = 行号      "1"
tr.children[1] = 字段名    "项目名称"
tr.children[2] = 值        "国土绿化示范项目元江片区"     ← 值在这里
```

而 v0.28 的代码按"只有 字段/值 两列"写成了 `tr.children[1]` → 取到**字段名**。
`formGrid.getData()` 返回的才是干净的两列 `[["项目名称","国土绿化…"], …]`。

**为什么后果这么严重**：读错的值进入 `allRows` 后，`buildSaveJob()` 判定"与已保存版本有差异"
→ 触发保存 → **字段名被写进数据库**。读取错误 + 自动保存 = 数据损坏。

> ⚠️ 这个错误的信号其实早就出现过：我在 v0.28 的浏览器调试里打印过
> `值格HTML片段: "验收备注"` —— 那就是"值格里放着字段名"，但我当时正专注查 `input` 事件，
> **看到异常数据却没追**。教训：调试时打印出来的"不该长这样"的值，必须当场解释清楚再往下走。

## 四、为什么能精确还原

**靠 `accept_logs`**。`api_save_row` 每次审计字段变化都记录 `old_value` / `new_value`，
所以事故写入在日志里留下了完整的"污染前真值"：

```
wb=6 row=0 验收人 : '何明星' -> '验收人'
wb=6 row=0 验收结果 : '不合格' -> '验收结果'
...
```

还原脚本（`/tmp/repair2.py`）的逻辑：

1. 采集"事故日志"：`new_value == field`（把字段名写进该字段）
2. 按 (工作簿, 行, 字段) 分组取**最早**一条 → 其 `old_value` 即污染前真值
3. **若该格子之后还有"非事故"变更 → 跳过并报告**，交人工确认（避免覆盖用户的新填写）
4. 否则还原该格子，并删除对应的事故日志（它们记录的是软件缺陷，不是业务变更）

线上 12 处**全部满足条件、无需人工确认**；执行前先备份数据库
（`data/app.sqlite3.bak_20260917_111631`）。

## 五、修复（v0.28.2）三重保险

```js
// ① 值来源优先用官方 API，不猜 DOM 位置
let v = (data[y] && data[y].length > 1) ? data[y][1] : '';

// ② 编辑中未提交的值取「最后一个格子」里的 <input>（值列永远在最后）
const vcell = cells[cells.length - 1];          // 不写死下标，首列有没有行号列都不影响

// ③ 安全闸：读到的值若等于该行自己的字段名 → 判定读错，丢弃并 console.warn
if (nv === h) { console.warn('[syncGrid] 读到字段名而非值，已忽略：', h); return; }
```

`captureCellEvent` 同一处错误也修了：原来 `x !== 1` 判成字段格（**真实输入因此根本收不到**，
这正是"逐键捕获一直没生效"的另一个隐藏原因），改为 `x !== tr.children.length - 1` 并加同一安全闸。
