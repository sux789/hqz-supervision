# 054 - v0.54 迭代记录_两张公共核验表与环节级「需先核验」软提示

> 七段式。第 6 段反转记录不可省。

## 1. 需求背景（用户原话）

> 「苗木核验 不知道要插入那个哪一个环节，肥料也是，是否插入两个 sheet，
> 如果 流程-回塘底肥 的第二个环节 需要 肥料核验，对应控件插入某个 标识，
> 需要进行 提示进行苗木核验 这个 操作 也可以操作公共流程 苗木核验，同理 肥料核验也是，
> 这样是否合理？是否有更好方案？列举场景我确认后再执行」

四轮拍板（用户选择）：

| 问题 | 结论 |
|---|---|
| 拆两个 sheet | **拆**：`流程-苗木核验` / `流程-肥料核验` 各一条公共流程 |
| 标识放哪 | **环节表新增「需先核验」列**，不塞进控件 DSL |
| 提示强度 | **软提示 + 一键跳转**，绝不拦截工序提交 |
| 挂点 | 肥料 → `流程-回塘底肥` 环节 2；苗木 → `流程-栽植撑杆覆膜` 环节 1 |

## 2. 验证结果（改前现场）

- v0.53：材料核验是**一条**项目级流程、两个环节，只在小班面板顶部显示状态；
  现场做到「有机肥1.5kg/株」时不知道这批肥验没验，得先退到工具栏再点进去 —— 多一步、容易漏。
- 改前实测（UI）：点「去核验」按钮**没反应**，原因是流程因前置未做被锁时，
  `renderV2` 把卡片里所有 button 都置灰，跳转按钮也被连坐（同一处在 v1 `render()` 也有一份，改错了一轮）。
- 改前 `tools/check_flow_tpl.py` 会把两条序号 0 的独立流程报「序号重复」、
  把「关联小班」多选报「选项少于 2 个」—— 均为误报。

## 3. 设计方案（逻辑+口径依据）

- **两条维度不混**：上排按小班（工序），下排按批次（公共核验）。公共流程不进小班下拉、
  不挂小班档案、**不锁工序**（v0.37 纪要红线）。若做成硬闸门，一批肥没覆盖到的小班永远做不了回塘底肥。
- **标识在环节表第 9 列**：「需先核验」填公共流程名（可 `;` 分隔多个）。
  不放控件列，因为控件 DSL 是「这一格填什么」，前置依赖是「这环节要先看什么」，
  两者混写会让控件解析 / 通过判断 / 模板体检全开特例，业务专家写错也不好报错。
  解析期校验引用必须是**确实存在的项目级流程**，写错直接报错（表名 + 行号）。
- **软提示**：环节卡片顶部一行「需先核验：肥料核验 ⚠ 未完成 · 去核验 →」，
  按钮即使流程被前置锁住也可点；「通过 / 不通过」照常提交，服务端零新增闸门。
- **一键跳转闭环**：点状态行任一项或卡片按钮 → 记住来路（wid / 小班 / 当前流程）
  → 直接打开对应公共流程（带 `flow` 参数）→ **自动预勾当前小班号** → 提交后**回到原小班原流程**。
  从工具栏自己进的不算跳转，不会乱跳回去。
- **两条表各自独立**：各自的进场批次号、核验项、附件、结论、关联小班、覆盖判定；
  小班状态行多条时给每项带流程名（流程名与环节名相同则不加前缀，避免「苗木核验·苗木核验」）。

## 6. 反转记录

- **反转 v0.53「一条材料核验流程、两个环节」**：苗木和肥料到货时间、附件、批次号都不同，
  合成一条会共用一个批次号；拆成两条公共流程，各自独立留痕，也更贴「两个 sheet」的业务直觉。
- **反转「标识写进控件」的直觉**：塞进 `选项(...)` 会污染 DSL；改到环节表新列，
  与 v0.53 的「作用对象」同属环节级声明，业务专家填表时一横排就能看完。
- **反转「提示 = 拦截」**：v0.36 起前置环节是硬闸门，但材料核验跨小班，硬拦会锁死未覆盖小班；
  本版明确软提示，服务端一行闸门都不加，并用 M9 固化这条口径。
- **反转 v0.52「状态行只读」**：现在每项可点直达对应公共流程，通关闭环带预勾与返回。
