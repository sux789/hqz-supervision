## C01 参数驱动（v0.1）

数据 sheet 的展示/编辑/拍照/搜索行为一律由「参数」sheet 驱动，代码禁止硬编码照片命名、目录、可编辑列、搜索控件等约定。
背景：hqz-survey 的历史教训——buildPhotoName/photoSaveSubdir 硬编码于 app.js，换模板就要改代码。

<a id="c02"></a>
## C02 参数 sheet 语法（v0.1）

表头固定 `key|value|类型|默认值|说明|示例`；多值 `;`、项内子字段 `|`、目录 `/`、文件名段 `_`、占位符 `{{}}`；解析器遇到未知 key 或违规分隔符必须报错（带行号），不静默跳过。
权威规范见 `doc/025-参数sheet配置规范.md`。

水印首行 = 拍摄时刻时间戳 `yyyy-MM-dd HH:mm:ss`（本地时区，前端固定行为），正文 = 「相片备注」模板渲染，均不随模板变化。

## C07 相片不在服务器长期存储（v0.9）

拍照仍优先存本地（App 存系统相册 / 浏览器下载），无预览（v0.8.1 起仅显示完整文件 path）；云同步开启时经服务器中转（/api/photo），七牛 zz-1 暂存 + data/pending 缓冲 → 百度网盘，百度成功即删 pending，七牛副本按保留期（默认 30 天）清理。
反转记录：修订 v0.8「完全不落服务器」——为可靠性引入中转+暂存，但成功即删不长期存储。
排查「照片没同步」：第一步先看后台 `sync_enabled`，再看 data/pending/ 是否积压。

导出 = 上传时原样留存的 source.xlsx(.xlsm) 清数据行后回填，禁止白板重建丢格式；静态 JS 引用必须带 `?v=版本号` 熔断缓存。

## C09 视频只存本机（v0.11）

App 内「🎬 视频」直接在页面录制（MediaRecorder 按后台「视频压缩」参数边录边压），停止后**仅保存到手机**（原生 saveVideo→Movies 相册【需新版 APK】/ saveFile→下载目录 / 浏览器下载），并在本机记录路径提示；不调用任何上传接口、不入七牛/百度、服务器无副本；**容器只认 MP4/H.264**（本机不支持则改走系统相机录制，保证可播放）。

## C10 压缩与同步解耦（v0.16）

图片压缩、视频压缩、云同步是三件独立的事，后台分三块各自保存；压缩在手机端/本地完成（关掉同步也照常压缩），同步只决定照片是否上云（视频永不上云）。

反转记录：修订 C01「一律由参数 sheet 驱动」——图片压缩增加服务器级缺省（sheet 仍优先）。

<a id="c11"></a>
## C11 唯一键与通用化（v0.23）

完整细则（七条）：
① **数据 sheet 定位**——优先精确取名为 `data` 的 sheet（此时多余 sheet 可容忍），否则要求"有且仅有 1 个非「参数」sheet"（旧模板兼容），否则**明确报错**，禁止静默取第一个；
② **行标识**（照片归档目录、变更日志、导出定位）一律取参数 `unique-key` 声明的列，未声明才回落 `小班号`，代码与前端禁止再硬编码「小班号」；
③ `unique-key` 只认这个英文名，值必须是数据表真实表头、只能一个列名、**不得出现在「可编辑列」**中；
④ 声明后该列**必须非空且唯一**，违反则拒绝上传并报错带 Excel 行号；**未声明则不校验**（旧模板零改动）；
⑤ 审计字段由参数 `日志字段` 驱动，百分比列由参数 `百分比列` 驱动（缺省回落旧规则），**且前端「结果联动」的字段必须复用后端下发的 `log_fields`，不得再写死一份**；
⑥ 必填 key 按需化——`可编辑列`/`功能` 恒必填，`相片备注`/`相片文件名`/`目录` 仅在「功能」含 拍照/视频 时必填；
⑦ 删除工作簿必须连带清理 `data/workbooks/<id>/`（源模板）与 `accept_logs`/`photo_sync` 关联行。
总目标：**同一套 App 装不同类型的 Excel，尽量不改代码**。
反转记录：反转 v0.1 起的隐含约定「数据 sheet = 第一个非参数 sheet」「行标识恒为小班号」「拍照三件套恒必填」。

## C12 多应用同域部署（v0.23.1）

`'/'` 是网关首页（所有应用的入口），硬编码 `'/'` 的后果是真实发生过的：用户被丢进别的应用、再拿本应用账号反复试密码（2026-09-14 何明星「退出」实测踩此坑）。

<a id="c13"></a>
## C13 可见性与权限分开（v0.24）

细则（四条）：
① **「下架」是软删除**——`workbooks.is_active=0` 只让 App/user 端看不见、不能操作（列表不列、读/写/导出/拍照/录像一律 403），数据行/源 Excel/日志/照片全部保留，管理员始终放行且可「恢复」；彻底删除只走 `DELETE ?purge=1` 且只暴露在已下架列表里。
② **前端隐藏一律不构成权限**：真正的边界只在服务端的 `@login_required`/`@admin_required`；**禁止**用 URL 参数（如 `?showdel=1`）当权限或"危险模式"开关——它会因被存书签而常开、会随链接扩散、会被后来人误当成权限，属于假安全。
③ **不可逆操作必须要求照着输入对象名称确认**（不是一键 confirm），且用自建 DOM 弹层而非 `window.prompt`——Android WebView 默认不实现 `onJsPrompt`，手机上会失效。
④ **标志位为 0 时不得写在 `or` 左侧**——`x or 1` 会把 0 吃成 1，导致守卫永久失效。

<a id="c14"></a>
## C14 保存与离场纪律（v0.25）

细则（六条）：
① **任何防抖/节流保存都必须能在离场前被冲刷**——点返回、路由切换、切后台、关页/重载四条路径全都要调 `flushRowSave()`，卸载时用 `fetch(keepalive:true)`（**禁用 `sendBeacon`**：它带不了 `X-Sup-Token` 头，只能把令牌塞 URL → 落进访问日志）。
② 待保存任务必须**快照 wid/ridx/values**，禁止延后到触发时才按 `cur/curIdx` 取值（切了工作簿会把 A 的数据写进 B）。
③ 编辑器（jspreadsheet）的 `onchange` 只在 blur/Enter 触发，因此必须**另加逐键捕获**（委托 `input`）把最新输入同步进内存，否则离场冲刷上去的是旧值。
④ `datetime`/`date` 判断**必须先 `datetime` 再 `date`**（datetime 是 date 子类，且 `str(datetime)` 会带 `00:00:00` 污染数据）。
⑤ 后台「下载 Excel」的筛选**只筛行**，字段由参数 `导出筛选`（`字段|select` / `字段|date`）声明，弹框只显示**声明 ∩ 该工作簿表头**的字段（没有的字段不提示），下载接口也只认声明过的字段（多传的参数一律忽略）；下拉候选值必须**三路合并**（该列对应的「`<列>选项`」参数枚举 + 列名含「人/员」的列并入系统用户名单 + 数据里出现过的值），否则空数据时下拉是死的。
⑥ 从登录页回跳要带 `?next=<原页面>`，登录后送回原页而非首页；非管理员则静默回 App 并清掉 `next`。

<a id="c15"></a>
## C15 就地更新与合并（v0.26）

细则（七条）：
① **「更新 Excel」必须就地更新、保留原工作簿 id**（`accept_logs` 绑 workbook_id+row_idx、下架状态、App 使用习惯都靠它不断链），只有「上传」才新建。
② 合并**以既有行顺序为基准**：匹配的行**原地**合并（老行 row_idx 不变 → 变更日志不错位），新表的行**追加末尾**，旧表有而新表没有的行**保留不删**。
③ 冲突取值：**只有「可编辑列」（旧∪新）的旧值非空优先**，**其余列以新表为准**——否则"填到一半改 Excel"（改原始数据、加列）永远不会生效。
④ 按**列名**对齐（列可增删换序），输出列序=新表列序；数值类型必须保留（别把 108.87 变文本）。
⑤ **不设"重合比例"自动闸门**：改为「预览统计（匹配/新增/仅旧/冲突/被清空/被删列字段）+ 输入工作簿名确认」；`?dry=1` 只算不写。
⑥ **必须可回滚**：写库前自动备份 DB 行 + 源模板文件（`workbook_backups`，每簿最多 5 份），`POST /rollback` 还原。
⑦ 唯一键列名两边不一致、或该列在任一侧缺失 → **拒绝更新**。
反转记录：反转 v0.1 起「改模板只能重新上传（= 新建工作簿）」。

<a id="c16"></a>
## C16 前端脚本健壮性（v0.27）

`null.addEventListener` 抛 TypeError 会让**整个脚本加载失败、整页失效**，且症状是"所有按钮都没反应"，极易误判成后端问题——这就是为什么禁止顶层裸 `addEventListener`。删元素前先确认引用处已包 `on()`。

<a id="c17"></a>
## C17 不可假定第三方组件的行为（v0.28）

细则（四条）：
① 对编辑器/第三方库，**关键数据不得依赖"它会不会派发事件"**——混淆源码里无法确认时，就当作"不会派发"来设计；在离场/承载边界上**直接读 DOM** 取真实值（编辑器在编辑时取 `<input>.value`，否则取单元格文本）。
② **关键写入必须有落盘草稿**：每次改动同步写 `localStorage`（同步写入，进程被杀也不丢），启动/切回前台自动补交，补交成功才清；国产 ROM 会在后台冻结定时器，因此"切回前台"也要触发补交。
③ **切后台时顺序必须是"先收值再冲刷"**——编辑器往往还没提交，不先收值等于什么都没存。
④ **验证不得自证循环**：自己 `createElement` 造输入再派发事件、然后观察自己的监听器，只证明"监听器存在"，**不能证明真实输入会触发它**；必须走真实交互路径（真实点击/键入）才算验证。

<a id="c18"></a>
## C18 用户打扰必须幂等（v0.28.1）

背景事故：页面被系统重载（录像/拍照走系统相机时国产 ROM 常重载）后内存标志归零，"只弹一次"变成**每次回来都再弹一次**（用户实测："视频保存后华为弹出应用信息"）。
原生侧同类动作（如跳厂商引导页）要**先判断"是否已满足"再跳**，不要无条件执行。

<a id="c19"></a>
## C19 从 UI 读值回写数据（v0.28.2，事故复盘）

**起因：v0.28 把字段名当值写坏了线上 12 处**——信号已出现在调试输出里却被跳过，且调试直接落在真实工作簿上。完整教训五条：
① **读值优先用官方 API**（如 `formGrid.getData()[y][1]`），**DOM 取值禁止写死下标**——表格常按「行号列 + 字段列 + 值列」渲染，`children[1]` 是字段名不是值（`children[length-1]` 才是值列）。**结构必须实测**（一行 `console.log` 即可），不得按"应该是几列"推断。
② **必须有 sanity 闸**：读到的值若等于该行自己的标签/字段名，判定为读错 → 丢弃并 `console.warn`，绝不落库。
③ **任何"读→自动保存"的链路必须先确认读源正确**：读错值 + 自动保存＝静默数据损坏；且**调试输出里"不该长这样"的值必须当场解释清楚再往下走**。
④ **验证一律用临时数据**，禁止拿真实工作簿做调试。
⑤ **审计日志要记 `old_value`**——本次事故全靠它精确还原被覆盖的真值。

<a id="c20"></a>
## C20 照片 EXIF 回写（v0.30，doc/017）

细则（三条）：
① 压缩（Canvas 重绘）**必然丢全部 EXIF**，要保留只能在压缩后用 piexifjs 把原片 EXIF 回写进压缩图（改网页端即生效，无需出包）。
② 回写时**三类标签必须处理**：`Orientation` 强制 1（像素已被 `createImageBitmap(from-image)` 摆正，保留原方向会被支持 EXIF 的查看器**再次旋转**）；删 `ImageWidth/Length`、`PixelX/YDimension`（像素已缩放，旧尺寸是脏数据）；删 `MakerNote`（厂商私有块偏移绑定原文件，整段拷贝会解析出乱码）。
③ EXIF 属锦上添花：读取/回写任何失败都必须**静默退回原行为**（设备定位+当前时间），绝不能因它丢照片。

<a id="c21"></a>
## C21 持续采集所有权在原生（v0.32，v0.33 修订；doc/020、022）

细则（六条）：
① **采集生死只由「定位权限」决定**——`load()`/`handleOnResume()`/授权回调三处幂等自启，禁止再把开始/停止绑在页面按钮上（页面会被重载、会被切走，权限不会）。
② 网页会从**两条路收到同一个点**（`drain` 回填 ∩ 实时回调流），必须按 GPS 时间戳去重 + localStorage 水位线（已上传到的最大 t）双闸，否则跨段/跨重载必重复。
③ 缓冲**必须先落文件再谈内存**：进程被杀时 location 型前台服务一起没，内存缓冲全丢，`files/track_buffer.csv` 是唯一能救回已采点的东西。
④ **上传失败绝不清缓冲**（林区无信号是常态，清了=丢数据）；上传成功才清，且上传窗口内到达的"迟到点"必须留在会话里归下一段。
⑤ 权限弹窗只能有一个出口（`ensurePermissionsUpfront`，localStorage 记问过），插件自身不再弹——否则授权回调到达时二次弹窗（C18）。
⑥ 「完全弃用网络定位」要**连 WebView `watchPosition` 回退一起删**：原生只注册 `GPS_PROVIDER` 而网页回退走 fused，混进来的基站/WiFi 点是 GCJ-02 且绝对精度仍 50~1000m，**比轨迹空白更糟**。
v0.33 反转（doc/022）：应用户要求改为**手动开关**——开关本身仍持久化在原生侧（SharedPreferences），网页按钮只是遥控器，重载/息屏不丢状态；权限仍是前置条件；轨迹按小班归属（开始时快照，上传文件名含小班）。

<a id="c22"></a>
## C22 语法兼容 + 报错可观测（v0.32.1，doc/021）

**起因：SM-G9860 Android 9 / WebView Chrome 73 上 `??` 语法让 app.js 整段 SyntaxError 报废**，症状"零请求、按钮全没反应"——与 C16 同款表象，故两条常一起排查。
排查顺序（三层日志）：后台「运行日志」卡片 → js.log 找 SyntaxError/资源失败 → app.log 找 `[flow]`/`[EXC]` 条目（快捷方式：`bash tools/log.sh`）。
补充：`node --check` 只证明当前 node 语法正确，**不能证明老内核可用**。
