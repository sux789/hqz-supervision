# 055 - v0.55 迭代记录_材料核验提示移到流程前面、已核验不显示

> 七段式。第 6 段反转记录不可省。

## 1. 需求背景（用户原话）

> 「材料核验是否显示到有 需要核验 的 流程前面 如果已经该小班 已经核验过了就不显示 合理再执行」

判断：**合理**，但只对一半就做会丢提醒 —— 若严格「只在有需核验环节的流程前显示」，
打开「整地」时苗木/肥料待办就完全看不见，现场开工前反而漏掉。
所以按「流程前面 = 流程内容（环节卡片）之前」实现，并保留精简总览兜底。

## 2. 验证结果（改前现场）

- v0.54：小班面板顶部**无条件**显示状态行（含 ✓ 已完成），环节卡片里再显示一条
  「需先核验 … ⚠/✓ 去核验」→ 同一个提醒出现两遍，已核验完的小班还有一条绿条，噪音大。
- 改前截图（430px）：`flow-head` 正下方即状态行，位于流程下拉之前，与工序顺序无关。

## 3. 设计方案（口径依据）

- **位置**：`flow-pick`（流程下拉）之后、`flow-card`（第一张环节卡片）之前 —— 即「流程前面」。
  DOM 实测顺序 `flow-pick(1) → flow-mat(2) → flow-card(3)`。
- **只列未完成项**：`m.steps` 里 `ok=false` 的才渲染；已核验项不出现；
  该小班**全部核验完 → 整块不显示**（不再有绿条）。
- **贴工序**：当前流程的 `need_flows` 引用到的未完成项排最前，加「本流程」角标；
  其余未完成项作为总览继续列出（整地等流程也能看到待办）。
- **一键跳转闭环保留**：点任一项仍直达对应公共流程、自动预勾当前小班、提交后回原处。
- **不显示后怎么看批次号**：需求要求"已核验就不显示"，故界面不留常驻入口；
  批次号与结论仍在工具栏「🧱 材料核验」的提交日志里可查（说明页第十节已写明）。

## 4. 代码修改（文件+要点）

- `static/flow.js`：`renderV2` 移除 `flow-head` 后的旧状态行调用，改在 `flow-pick` 后插入；
  `materialHtml(m, steps)` 重写（收集 todo / refs / here / other，只输出未完成项，全完成返回空串）；
  删除环节卡片里的 `.flow-need` 重复提示；`bindV2` 只绑 `[data-mat-flow]`；
  两处禁用循环恢复原样（提示块已不在卡片里，不再需要豁免）。
- `static/style.css`：删掉废弃的 `.flow-need*` 规则；新增 `.mat-here` 角标。
- 模板（两份）：「说明」页升 **v3.5**，第十节「软提示」「一键跳转」两行改写为新位置与
  「已核验不显示」口径，并注明批次号去提交日志查。模板结构（9 列、7 张流程表）未变。
- `templates/index.html`：静态资源 `?v=0.55.0`。
