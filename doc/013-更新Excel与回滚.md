# 013-更新 Excel（按唯一键合并）与回滚（v0.26）

> 版本：v0.26 ｜ 日期：2026-09-17 ｜ 状态：已实现并本地实测通过
> 关联约束：**C15（新增）**、C01、C11、C13、C08

## 一、需求与判断

用户提出：后台在「下载 Excel」下面加一个**「更新 Excel」**，如果有唯一键、唯一键有一定比例重合，就
「更新或添加一定量的值」。用途：**填到一半要改 Excel**，或者**要加「导出筛选」等参数**。

### 1.1 先说两个查出来的事实（决定了方案）

| 事实 | 验证结果 | 意义 |
|---|---|---|
| 重新上传会不会覆盖？ | **不会**。上传永远 INSERT 新行（实测 ids `[2,3]` → `[2,3,66]`），旧的连同已填数据原样保留 | 所以"数据丢失"其实不是丢，而是**变成了两个工作簿**：新的空数据 + 旧的有数据，得手工迁移 |
| 现有有没有迂回路径？ | **有**。导出的 Excel 里**带「参数」sheet**（实测 sheets = `['中幼林抚育验收','参数']`） | 「下载 → 改参数 → 重传」能保住数据，但会多出一个工作簿、要手动清理旧的 |

**真正的痛点不是"丢数据"，而是"工作簿 id 变了"** —— `accept_logs` 绑 `workbook_id + row_idx`、
下架状态、App 端的使用习惯全部断链。

### 1.2 判断：方向合理，但要改两点

| 用户设想 | 采纳的改法 | 理由 |
|---|---|---|
| 靠唯一键**重合比例**决定能否更新 | **不设自动闸门**，改为「预览统计 + 输入工作簿名确认」 | 阈值会误伤：删掉一批小班后重合率可能很低，但仍是同一份数据；传错文件也可能凑巧重合。把「匹配 / 新增 / 仅旧数据 / 冲突」摆给用户看，比一个数字可靠 |
| 「更新或添加一定量的值」 | **以既有行顺序为基准**：匹配的行**原地**合并，新表的行**追加末尾** | 老行的 `row_idx` 不变 → **变更日志不会错位**（顺序全打乱的话日志就废了） |
| —— | **保留原工作簿 id** | 变更日志、下架状态、App 使用习惯全部保住。否则和重新上传没本质区别 |

### 1.3 一处必要的细化（否则达不到"能改 Excel"的目的）

用户选的是「App 已填的优先」。如果理解为**所有列**旧值优先，那么用户在新 Excel 里改的
`小班面积`、修正的原始数据、新增列的取值**永远不会生效**（旧行那些格子非空）—— 功能就废了。

因此规则收窄为：

> **只有「可编辑列」（人工在 App 里能填的列 = 旧表可编辑列 ∪ 新表可编辑列）旧值非空优先；
> 其余列以新 Excel 为准。**

这样"填到一半改 Excel"才真的能改：人工填的验收结果保得住，模板原始数据又能被新表修正。

## 二、语义（C15）

### 2.1 合并规则一览

| 情形 | 处理 |
|---|---|
| 唯一键在两边都匹配上 | **原地合并**（保持老行位置）：可编辑列的旧值非空 → 用旧值；否则用新表的值 |
| 唯一键只在旧数据里 | **保留**该行（不删）；按新表列序重排，新表新增的列留空 |
| 唯一键只在新 Excel 里 | **追加到末尾** |
| 新 Excel 加了列 | 老行这些列取新表的值 |
| 新 Excel 删了列 | 该列数据丢弃，统计 `dropped_nonempty`（有几个非空格子会丢） |
| 新 Excel 该格为空、旧表有值（非可编辑列） | 取新表的空值 → 统计 `blanked_nonempty`，**弹框要警告** |
| 新 Excel 唯一键有重复 | 无法判断更新哪一行 → 重复行**当新行追加**，统计 `dup_new_key_count` 并在弹框警告 |
| 唯一键列名两边不一致 | **拒绝更新**，提示"两边 unique-key 需要一致" |
| 唯一键列在任一侧缺失 | **拒绝更新** |

### 2.2 两步走 + 可回滚

- `POST /api/workbooks/<id>/update?dry=1` —— **只算不写**，返回统计供确认
- `POST /api/workbooks/<id>/update` —— 正式提交，需 `confirm=<当前工作簿名>`（C13 的确认规矩）
- 写库前自动备份（DB 行 + 源模板文件），`POST /api/workbooks/<id>/rollback` 可还原
- 每个工作簿最多留 `MAX_BACKUPS = 5` 份备份，超出的连同其源模板备份文件一起清

### 2.3 更新的内容

| 字段 | 是否更新 |
|---|---|
| `headers` / `rows` | ✅ 合并结果 |
| `config`（参数）/ `param_rows` | ✅ 用新 Excel 的（这样加「导出筛选」立刻生效） |
| `key_column` | ✅ |
| `name` | ✅ 换成新上传的文件名 |
| `sheet_name` | ✅ |
| **`id`** | ❌ **保持不变** |
| **`is_active`** | ❌ 保持不变 |
| `source.xlsx` | ✅ 换成新模板（导出按新模板回填）；扩展名变了会清掉旧的那个 |
| `accept_logs` / `photo_sync` | ❌ 不动（老行 row_idx 未变，日志仍指向正确的行） |

## 八、使用提示

- 建议**先「下架」再更新**：避免同事正在 App 里填写时被合并结果覆盖。
- 更新前若发现"新 Excel 那格是空的"，弹框会警告会有多少格被清空 —— 先补好再上传。
- 一次更新只保留一步的回滚；连续更新两次后，回滚只能回到**最近一次**更新前。
