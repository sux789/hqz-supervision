## 1. 总览：四层 33 因素

「顺」不是单点技巧，是四层互相咬合的结果：

| 层 | 因素 | 一句话作用 | 本项目实测证据 |
|---|---|---|---|
| **协作层**（怎么指挥） | C1-C8 | 让 AI 第一次就做对，减少返工轮次 | 019 复盘：14 条指令中 12 条有效 |
| **资产层**（沉淀什么） | A1-A8 | 让每次迭代站在上次积累上，不从零开始 | 45 篇迭代文档 + 8 真实用例 |
| **工程层**（代码基建） | E1-E11 | 让 AI 找得到、看得见、改得稳 | v5 重构 37523 单元格 0 回退 |
| **节奏层**（迭代纪律） | R1-R6 | 让复杂度不爆炸，决策可追溯 | v4.19 显式反转 v4.18，有据可查 |

**核心结论**：协作层决定「方向对不对」，资产层决定「积累丢不丢」，工程层决定「改动稳不稳」，节奏层决定「债务滚不滚」。四层缺一，项目越大越卡。

## 2. 协作层因素：指挥 AI 的 8 个高效模式

### C1 遇错先跑再分析，不让 AI 猜

- **实测**：用户说「执行一下看哪儿错了，再分析」，错误信息直接定位「材积式代码0不存在」，一轮解决；反例是桦木问题靠猜改了 3 次（加字典→改出材率→才发现该读 sheet）。
- **普遍化**：任何「文件报错/结果不对」类问题，第一个动作是让 AI 跑一遍拿真实报错，不是让它读代码猜。

```text
话术模板：「先执行看错误信息，再分析根因，不要猜。」
```

### C2 指令给方向和边界，不给模糊目标

- **实测**：「按兼容性最好的方法改」→ AI 选了「Excel 读取 + 内置回退」而非只改字典；「不要改模板改代码」→ 防止越界改 tpl。
- **普遍化**：方向词（兼容性/性能/最小改动）+ 边界词（不改 X 只改 Y / 待确认前不操作），能阻止 AI 自作聪明扩大改动面。

```text
话术模板：「按 [兼容性最好/最小改动] 的方向改；不改 [模板/数据]，只改代码；[XX] 待确认前不做任何操作。」
```

### C3 提交前强制自审

- **实测**：「检查这次改动是否合理，不合理退回」→ AI 自审发现龄组推导与原始数据矛盾（40 年=中龄林被推导成成熟林），主动退回，阻止错误入库。
- **普遍化**：对「推导/默认/映射」类逻辑，提交前必要求 AI 对照原始数据自审。这是成本最低的质量门。

```text
话术模板：「提交前对照原始数据检查合理性，不合理退回，尤其是推导和默认值逻辑。」
```

### C4 针对性提问触发验证，而非泛泛「检查下」

- **实测**：「生成文件纵坐标 label 是否丢失」→ 精准发现值填到标签位的 bug。泛泛的「检查下有没有问题」几乎查不出东西。
- **普遍化**：用「X 是否丢失/正确/一致」的具体疑问句，AI 会写脚本逐点验证。

### C5 大改动先文档后执行

- **实测**：45 字段纵向布局改造，先写字段清单/映射/迁移步骤文档对齐，再动手，一次通过。
- **普遍化**：凡涉及 >3 个文件或数据结构变化的改动，先出方案文档，确认后执行。边想边改必然返工。

### C6 每版留痕：提交 + 迭代文档

- **实测**：「提交写迭代文档」→ 45 篇编号文档成为项目最大资产之一，任何决策可回溯到原始需求和测试数据。
- **普遍化**：git commit 记「做了什么」，迭代文档记「为什么这么做 + 验证结果 + 反转记录」。两者不可互替。

### C7 指令精确到坐标：单元格/行号/积木编号三级定位（新增）

- **实测**：本项目高效指令全部带精确坐标——「附表5 E6/F6/H6 必须等于分类行之和」「汇总表 S3:T3/U3:V3 表头值交换」「gen.py L783-786 列赋值同步交换」「改 B5 的加权逻辑」。AI 零歧义一次做对，无需返工确认「你说的是哪」。
- **普遍化**：指令定位三级体系——**积木编号**（改哪段逻辑）→ **文件:行号**（改哪处代码）→ **单元格/字段名**（改哪个数据位）。模糊指令（「改下汇总表」）让 AI 先花一轮猜位置，猜错就返工。

```text
话术模板：「改 [积木编号] 的 [文件:行号]，把 [单元格X] 从 [旧口径] 改为 [新口径]，与 [单元格Y] 口径一致。」
```

### C8 不确定就列「待确认清单」，不猜（新增）

- **实测**：013 文档把客户 12 项问题逐条分析标注「已验证/待确认」；《客户问题分析与待确认事项》列 20 项已验证答案 + 6 项待确认——AI 不替客户做决定，列出来问，一次问全。
- **普遍化**：AI 遇到口径歧义/业务判断时，输出「待确认清单」（问题 + 候选方案 + 建议 + 依据），用户批量裁决。**猜错的代价 ≫ 问一轮的代价**。配合 A3 优先级索引：能按权威源自行判定的不用问，真正拿不准的才进清单。

```text
话术模板：「拿不准的不要猜，列待确认清单：问题/候选方案/你的建议/依据，我批量回复。」
```

## 3. 资产层因素：项目里沉淀什么最加速

### A1 真实输入用例库 + 黄金输出对（最高价值资产）

- **实测**：8 份真实录入文件（梁河 1 + 沧源 7）+ 对应客户原始附表，构成回归基准。每次改动全量跑 8 用例逐格对比，v4.33 改公式后靠它确认 AF=AC4/AG=AD4 一致才提交；v5 重构靠它证明 37523 单元格 0 差异。
- **普遍化**：项目第一天就收集 ≥3 份真实输入 + 期望输出（golden files），放进 `data/` 或 `tests/fixtures/`。mock 数据的边界情况永远不如真实数据。
- **扩展**：用例库要覆盖「正常 + 边界 + 会报错」三类，报错用例正好喂给 X1 异常演练。

### A2 模板即规格

- **实测**：录入模板用颜色编码（黄=必填、橙=关键关联、灰=表头只读），批注记录原纵向位置等元数据。横向重构时靠批注里的原位置一次改对。
- **普遍化**：项目里的模板/配置文件本身就是机器可读的规格，把约束写进模板（颜色、批注、数据验证），AI 读模板即懂规则，减少口头传达失真。

### A3 文件优先级索引

- **实测**：001 文档把信息源按权威性排序（P0 客户需求 > P1 国家规范 > P1.5 省细则 > P2 实际案例 > P3 培训材料），需求冲突时知道听谁的。
- **普遍化**：任何项目第一天就列「信息源权威性排序」，AI 遇到矛盾口径时按优先级取舍，不瞎权衡。配套 R5：优先级索引回答「听谁的」，差异归因回答「差在哪」。

### A4 编号迭代文档 + 反转记录

- **实测**：`doc/NNN-版本_主题.md` 三位数递增；v4.19 文档显式记录「反转 v4.18 列号方案为拼接字符串」；v4.28 反转 v4.19 的修枝填值逻辑。反转不掩盖，链条完整。
- **普遍化**：迭代文档七段式——需求背景(用户原话)→验证结果→设计方案→代码修改(文件+行号)→测试验证(用例+一致率)→反转记录→部署记录。
- **关键点**：**反转记录是最高价值段落**。决策反复是常态，显式记录反转链（谁反转了谁、为什么）防止 AI 把旧方案又改回去。

### A5 硬约束注册表（带版本号）

- **实测**：项目记忆维护「硬约束」清单，每条标注来源版本（如「附表5 F9=E9 — v4.16」「附表3 J5/X5 用 GCD 约分 — v4.19 反转 v4.16」），AI 跨会话不重复犯错。
- **普遍化**：即 X5 的落地——项目根放 `CONSTRAINTS.md` 随 git 走（模板见 9.2）。本项目靠外部记忆实现，新项目应第一天就内建。

### A6 对比/检查脚本工具链

- **实测**：`compare_*.py`（逐格 diff）、`inspect_*.py`（结构探测）、`validate_input.py`（输入校验）构成工具链，验证全靠脚本，不肉眼。
- **普遍化**：每个项目应有三个脚本骨架——`compare.py`（新旧输出对比）、`inspect.py`（输入/模板结构探测）、`validate.py`（输入合法性）。第 9 章给可直接用的实现。

### A7 一键部署脚本

- **实测**：`deploy.sh` 同步 tpl/ + forest_v4/ + 重启 gateway，部署无手工步骤。踩坑点已固化：rsync exclude 不带目录前缀、多 worker 共享 `.secret_key`、服务器装 Pillow。
- **普遍化**：部署脚本从第一次部署就写，踩过的坑立即注释进脚本，不靠记忆。

### A8 文件名即元数据 + 输入留档可复现（新增）

- **实测**：录入文件结构化命名 `录入_梁河县_遮岛镇_26林班_26小班_1样地.xlsx`——文件名自带路由信息，批量处理/定位/排错不用开文件；web 端上传文件按 `原名_IP_uid_时间戳.xlsx` 留档，任何线上结果可回溯到原始输入复现。
- **普遍化**：**文件名是免费的元数据通道**——把路由键（区域/批次/版本）编码进文件名，脚本和人都受益。所有进入系统的输入留档（原件 + 来源 + 时间），输出永远可复现；无留档的项目，线上问题 = 无法复现 = 无法修。

## 4. 工程层因素：代码基建 11 件套

### E1 积木 + 契约 + BLOCKS 注册表

- **实测**：38 文件项目，AI 先读 25 行 BLOCKS.md 按编号定位（「改 B5 的加权逻辑」），不盲读千行 gen.py。
- **普遍化**：一积木一文件一职责 <200 行；契约五要素（类型签名/前置/后置/错误/副作用）；BLOCKS.md ≤25 行放项目根。**AI 指令精确到积木编号。**
- **注意**：新项目先 B0 跑通 MVP 再拆（v3 单文件 800 行跑通业务才拆 v4/v5），没跑通就拆 = 空中楼阁。

### E2 debug 调用链（最小可用集）

- **实测**：`tag(BX_in/out) + file:line:func + 耗时ms + 变量摘要(类型+len+前2元素) + 调用链追加`，运行时一行调用链（B5→B6→B7-B13+耗时）数据流一目了然。
- **普遍化**：最小可用集优先，diff/JSON 模式按需（本项目 diff 实现后极少触发，JSON 未做也无碍）。禁止临时 print，预埋 debug 替代。

### E3 if_throw 案发现场 + 集中错误码

- **实测**：FATAL/WARN/SOFT 三档 + 错误码集中在 errors.py + BizError 自动附最近 N 条调用链，报错不重现场。
- **普遍化**：业务代码只 raise BizError，不 except 吞细节；顶层统一捕获输出「人话+机器码+定位+调用链」；错误带行号（每木调查林区/林班空值报错含行号，用户直接定位到 Excel 行）。

### E4 输出对比防线（改动安全闸，本项目价值最大发现）

- **实测**：重构/改算法后，新旧版双跑同一真实输入，逐 sheet 逐单元格 diff（容差 1e-4，区分 None/类型/数值），0 差异才放行。
- **普遍化**：**这是被最低估的因素**。注册表/debug/if_throw 让 AI「看得见找得到」，但只有输出对比能证明「改动没回退」。任何有确定输出的项目（文件/报表/API 响应）都能双跑对比。
- **配套**：对比出差异后按 R5 归因，不是见差异就改。

### E5 口径统一：显示值 = 计算值（源头取整）

- **实测**：v4.35 在 calc 源头 round，保证「W4×作业面积=Y4」「col18=col17-col20」等恒等式在显示值上严格成立——此前各表各自取整导致表间对不上，客户肉眼即可发现的低级信任危机。
- **普遍化**：**数值项目铁律——先定「显示位数=计算口径」，在数据源头一次取整，下游只做展示不再取整**。表间勾稽关系必须在显示值上成立，不是只在浮点上成立。

### E6 不臆造：校验失败原样报错 + 列可选值

- **实测**：拒绝「桦木→阔叶树」自动映射，原样报错列出 39 个有效代码；龄组无来源不推导，保持默认。
- **普遍化**：专业字段有参考表的原样校验、失败报错+列可选值；无来源的报错或默认，绝不自动映射/推导。AI 自作聪明的修正是最高频翻车点。拿不准的业务判断走 C8 待确认清单。

### E7 前置校验（唯一性/关键列，报错带行号）

- **实测**：reader 层做唯一性校验（三元组不重复、同一标准地号不对应多个林班、跨表林区林班一致），所有小区被跳过时必须抛错不静默生成空文件。
- **普遍化**：坏数据在入口处炸掉，带行号/字段名/当前值/可选值；绝不静默跳过——静默跳过的坏数据会在最下游变成无法归因的错数。

### E8 值与样式分离，模板样式不动

- **实测**：输出保留模板全部样式（边框/合并/字体/列宽），代码只填值不动样式；v4.14 修复「样式与值耦合」隐患。
- **普遍化**：凡是「模板 + 填值」类生成，代码写值前不清样式、不重建结构；写入前先确认标签位/值位（本项目翻过车：纵坐标值填到标签位覆盖标签）。

### E9 单一事实来源：跨表强一致读取，不重算（新增）

- **实测**：附表5 B15（目标树株数）直接读 `ws.parent["附表3"].cell(5,10)` 的值，不用本表数据重算——保证两表同一数字永远一致（v4.19）；附表5 H6-H10 留 Excel 公式 `=E-F`，展示层让表格软件自己算，代码不越俎代庖（v4.18）。
- **普遍化**：**同一事实只在一个地方算，其他地方引用不复制**。重算 = 两份逻辑 = 迟早漂移。衍生规则：展示层（Excel/前端模板）能内建公式的用公式，计算层才用代码——公式对用户可见可审，代码不可见。

### E10 运行间无全局残留（新增）

- **实测**：v4.14 修复「跨项目串数据」隐患——上一次运行的全局缓存/配置残留污染下一次运行，A 项目的数据串进 B 项目的输出。
- **普遍化**：每次运行 = 全新状态。全局缓存/单例/模块级可变状态在入口显式重置；配置每次运行重新加载，不跨运行复用。**判定方法：同一进程连跑两个不同输入，第二个输出必须不受第一个影响**——这应成为集成测试的固定断言。

### E11 WARN 汇总成交付报告，不逐个打断不淹没（新增）

- **实测**：v4.9 校验结果支持 `--report` 输出 `doc/校验报告.md`——8 个文件的 WARN 级问题（强度超限等）汇总成一份可交付报告，既不逐个打断流程，也不淹没在控制台刷屏里。
- **普遍化**：WARN 级问题的正确归宿是**结构化报告文件**（可交付、可归档、可追踪），不是控制台 print。控制台 print 的 WARN = 看过就忘 = 等于没报。报告带：问题项 + 位置 + 当前值 + 阈值 + 建议动作。

## 5. 节奏层因素：迭代纪律 6 条

### R1 小步迭代：一版解决 1-3 个问题

- **实测**：001 路线图即定「每次迭代解决 1-3 个积木问题，git 提交记录每次变更」，v4.2→v4.35 每版主题单一（看文档名即知改了什么）。
- **普遍化**：一个版本一个主题，文档名 = 版本号 + 主题。一版塞 10 个改动，出问题时无法归因是哪个改动引入的。

### R2 固定循环：需求→设计→实现→全量用例验证→迭代文档→部署

- **实测**：v4.34 表头交换完整走完：改模板+改代码→8 用例全量测试（表头/子表头/值类型断言）→写 044 文档→deploy.sh 部署。
- **普遍化**：循环里「全量用例验证」和「迭代文档」不可省。省了验证 = 赌，省了文档 = 失忆。
- **配套**：改口径类需求必同步改三处——模板 + 代码 + 测试断言（v4.34 教训：表头换了，代码列赋值和断言也要换）。

### R3 反转显式化

- **实测**：约束清单里「v4.19 反转 v4.16」「v4.28 反转 v4.19」链条清晰，当前有效口径一眼可辨。
- **普遍化**：决策反复时，新文档/新约束必须写明「反转了哪条旧决策、为什么」；旧决策不删，标注「已被 X 反转」。

### R4 版本号与约束关联

- **实测**：每条硬约束标注生效版本（— v4.16 / — v4.34），冲突约束按版本号判新旧。
- **普遍化**：约束/决策不带版本 = 无法判断新旧，AI 会随机选一个执行。

### R5 差异归因：谁对谁错分析，不默认改代码对齐（新增）

- **实测**：003 文档「谁对谁错分析」——生成附表 vs 客户原始附表有 873 项差异，逐项按规范判定后分三类：**生成对**（原始漏标 3 株干扰树，规范要求全采）、**原始对**（录入文件漏录柳杉树种）、**各有依据**（树高：计算均值 vs 工程师经验值）。最终 632 项剩余差异全部确认为数据源差异而非代码 bug。
- **普遍化**：对比发现差异时，**先归因再动手**，差异永远分四类：①代码 bug（修代码）②输入数据问题（修数据）③基准本身错（坚持生成值，向客户举证规范依据）④合理多解（记录容差）。**默认「差异=我错」是 AI 协作的隐性灾难**——为对齐一个错的基准改代码，等于把对改错。

### R6 减法设计：删比加更需要纪律（新增）

- **实测**：v4.8「输入优化做减法」砍掉录入模板冗余字段，录入负担立降；v4.15 v5 模板去掉自动 id 列，消除一类匹配错误。两次都是「删」解决「加」解决不了的问题。
- **普遍化**：每个迭代问自己「这版能删什么」——冗余字段、重复管线、僵尸代码、过度配置。**功能加法谁都会做，删法的收益（录入成本↓、错误面↓、维护面↓）长期复利**。删除前用 E4 输出对比证明行为不变。

### 9.4 `compare.py`（双跑对比闸，可直接用）

```python
"""新旧输出对比：改动后必跑。用法: python compare.py old_out/ new_out/
文本/CSV 按行对比；Excel 按 sheet!cell 对比（需 openpyxl）。退出码非 0 = 有差异。"""
import sys
from pathlib import Path

TOL = 1e-4  # 数值容差

def load_units(path: Path) -> dict:
    """输出 → {单元位置: 值}。按项目输出格式选实现。"""
    units = {}
    if path.suffix in (".xlsx", ".xlsm"):
        from openpyxl import load_workbook
        wb = load_workbook(path, data_only=True)
        for ws in wb.worksheets:
            for row in ws.iter_rows():
                for c in row:
                    if c.value is not None:
                        units[f"{ws.title}!{c.coordinate}"] = c.value
    else:  # 文本/CSV/md/json 按行
        for i, line in enumerate(path.read_text(encoding="utf-8").splitlines(), 1):
            units[f"L{i}"] = line
    return units

def diff(a: dict, b: dict) -> list:
    """差异列表: (位置, 旧值, 新值)。区分 缺失/None/类型/数值。"""
    diffs = []
    for key in sorted(set(a) | set(b)):
        va, vb = a.get(key, "<缺失>"), b.get(key, "<缺失>")
        if isinstance(va, (int, float)) and isinstance(vb, (int, float)):
            if abs(float(va) - float(vb)) > TOL:
                diffs.append((key, va, vb))
        elif va != vb or type(va) is not type(vb):
            diffs.append((key, va, vb))
    return diffs

if __name__ == "__main__":
    old_dir, new_dir = Path(sys.argv[1]), Path(sys.argv[2])
    total, all_diffs = 0, []
    names = {p.name for p in old_dir.iterdir()} | {p.name for p in new_dir.iterdir()}
    for name in sorted(names):
        fo, fn = old_dir / name, new_dir / name
        if not fo.exists() or not fn.exists():
            all_diffs.append((name, "文件缺失", ""))
            continue
        ua, ub = load_units(fo), load_units(fn)
        total += len(set(ua) | set(ub))
        all_diffs += [(f"{name}:{k}", va, vb) for k, va, vb in diff(ua, ub)]
    rate = 1 - len(all_diffs) / max(total, 1)
    print(f"总单元: {total} | 差异: {len(all_diffs)} | 一致率: {rate:.2%}")
    for d in all_diffs[:50]:
        print(d)
    sys.exit(1 if all_diffs else 0)  # 非 0 退出码 → 可挂 pre-commit/CI
```

## 11. 健康度度量（每周/每 5 版统计一次）

方法论有没有效，用数字说话，不靠感觉：

| 指标 | 计算 | 健康线 | 恶化信号 → 查 |
|---|---|---|---|
| **一次通过率** | 一次做对的需求数 / 总需求数 | ≥80% | ↓ → C2/C7 指令质量 |
| **返工轮次** | 平均每需求 AI 修改轮数 | ≤1.5 | ↑ → C1/C7/E6 |
| **对比一致率** | 双跑 diff 一致率 | 100% 或全部预期 | 非预期差异 → E4 没跑/R5 没归因 |
| **定位耗时占比** | 找问题位置耗时 / 总调试耗时 | ≤30% | ↑ → E1/E2/E3 基建缺失 |
| **文档同步率** | 有迭代文档的版本数 / 总版本数 | 100% | ↓ → R2 循环断裂 |
| **约束复发率** | 违反已登记约束的次数 | 0 | >0 → A5 未被 AI 读取 |

**用法**：首次统计即基线，之后看趋势不看绝对值。任何指标连续两期恶化，按第 6 章诊断表找缺失因素。

```text
│ 如果只记 6 条：                                                │
│  1. 真实用例双跑逐格对比，0 差异才提交（E4）                   │
│  2. 校验失败原样报错，绝不自动映射推导（E6）                   │
│  3. 遇错先跑拿报错，不让 AI 猜（C1）                           │
│  4. 显示值=计算值，源头一次取整（E5）                          │
│  5. 对比出差异先归因，基准可能才是错的（R5）                   │
│  6. 每次迭代写文档，反转显式记录（R2+R3）                      │
├────────────────────────────────────────────────────────────────┤
│ 卡顿时：查第 6 章失效信号诊断表，按症状找缺失因素。            │
└────────────────────────────────────────────────────────────────┘
```

## 13. 资产进化机制：去掉低价值，长出高价值（v2.1 新增）

模板不是一次性交付，是持续进化的资产组合。判据一句话：**每个资产必须能回答「它防住过什么错误、省过什么成本」，答不上就进观察名单。**

### 13.1 进化链：错误 → 自动化（防线逐级变硬，单步成本都 ≤10 分钟）

```text
翻车 1 次        → 写进 CONSTRAINTS.md 文字约束        （成本 1 分钟）
约束依赖人工记忆  → 写成 check_invariants.py 勾稽断言    （成本 10 分钟）
断言每次手动跑    → 挂 pre-commit / CI 自动跑           （成本 5 分钟）
同一人工动作重复 3 次 → 脚本化收进模板                  （Rule of Three）
```

**要点**：不跳级。没翻车就写断言 = 过度工程；翻车两次还停在文字 = 债务。文字管判断，断言管数学，CI 管纪律。

### 13.2 退化链：零引用 → 清除

```text
资产连续 5 版「未发挥作用」（STATE.md 活跃度表记录）
  → 三选一：修复（腐化就更新）/ 合并（两个半有用并一个）/ 删除（git 有历史，不心疼）
```

- **腐化不等评审**：BLOCKS.md / STATE.md 与代码脱节会误导 AI，比没有更糟，发现立即修。
- **删除不心疼**：git 保留全部历史，删的是维护成本不是信息。
- **合并优先于新增**：新需求先看能否并进现有资产，资产数量膨胀本身就是低价值化。

### 13.3 评审节奏

每 5 版或每月，10 分钟，两件事：① 对照第 11 章健康度度量看趋势；② 过 STATE.md 活跃度表，给每个资产标「保留/修复/合并/删除」。评审结果写进当版迭代文档第 5 段。
