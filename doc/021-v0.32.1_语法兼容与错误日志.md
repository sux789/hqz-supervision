# doc/021 — v0.32.1 老内核语法兼容 + 全链路错误日志

> 2026-10-14。起因：用户报"验收第一步提交弹红色错误"，问"能否看日志？语法错误也要捕获日志"。

## 一、排查结论（先于改动）

SSH 看服务器日志得到两个事实：

1. **当天上午的两次验收提交 POST 实际都是 200**（11:03:28 / 11:06:22，随后回读 flow 数据变大 = 落库成功）；
   error.log 里 supervision 最后一条异常栈是 09-13 的 `ModuleNotFoundError: track_export`（旧事）。
   → 服务器侧当时没有可看的异常，**红色报错拿不到现场**，这就是"要日志"的直接动机。
2. **决定性线索**：access.log 里一台 **SM-G9860（Android 9，WebView 内核 Chrome 73）**
   10:17~10:20 每隔十几秒只反复请求 `/favicon.ico`，**零 API 调用** —— 典型的
   "前端脚本加载即崩"（C16 症状）。排查发现 `app.js` 有 5 处、`admin.js` 有 13 处
   **`??`（空值合并运算符）**，Chrome 80 才支持；老内核解析到第一个 `??` 就
   **SyntaxError 整段脚本报废**，登录页之后的一切（包括提交按钮）全部无反应。

## 二、改动

### 1. 语法兼容（修根因）
- `app.js` / `admin.js` 全部 `??` 改为 `x != null ? x : 默认值`（`== null` 同时覆盖
  `null`/`undefined`，且保留 `0`/`''` 语义，与 `??` 等价）；
  这也是库里既有惯用法（`v == null ? '' : String(v)`），不引入新风格。
- **登记 C22**：静态 JS 只写项目最老实测内核（Chrome 73）支持的语法；`?.`/`??`/`replaceAll`/`Array.at` 等禁用。
- 注意 `node --check` 只校验当前 node 语法，**不能证明老内核可用**，别拿它当兼容性证明。

### 2. 全链路日志（让"红色报错"永远有现场）
| 层 | 触发 | 落点 |
|---|---|---|
| 前端 JS | `window` error（capture）= 运行时错误 + **`<script>` SyntaxError** + 资源加载失败；`unhandledrejection` = Promise 拒绝 | `POST /api/jslog` → `data/logs/js.log`（一行一条 JSON） |
| 服务端 | 蓝图内未捕获异常（`@bp.errorhandler(Exception)`，HTTPException 放行） | `data/logs/app.log`，带 user/路径/完整栈 |
| 验收提交 | `POST /api/workbooks/<id>/flow` 每种结局：成功 / 403 下架 / 400 参数·未命中·无环节·必填 / 409 转序 | `data/logs/app.log`，`[flow]` 前缀，拒绝带缺项明细 |

实现要点：
- 上报钩子是 **head 里第一段内联 script**（必须先于所有 `<script>` 才能抓到它们的语法错误），
  index.html 与 admin.html 各一份；每页最多报 10 条防刷；自身任何失败静默忽略（日志绝不能反过来搞挂页面）。
- `/api/jslog` **免登录**（登录页也可能炸）；字段截断（msg 500 / stack 1500 / ua 300）+ 文件超限截尾
  （app.log 5MB → 留 2000 行；js.log 2MB → 留 1000 行），纯标准库，杜绝日志把磁盘写爆。
- 后台新增「**运行日志**」卡片（admin_required）：并排显示 app.log / js.log 各最近 200 行，
  手机上出红色报错时，管理员不用 SSH 就能看到原因。

## 三、测试

- e2e 新增 **I 组 6 项**：jslog 免登录 200 / js.log 落盘 / admin 看日志 200 / 内容含上报 /
  非管理员 403 / flow 拒绝落 app.log。全量 **108 + 107 + 20 = 235 项全绿**。
- `node --check` 三个 JS 语法通过；`??` 复查 0 处。

## 四、遗留

- SM-G9860 那台修完仍需真机复测（没法远程验证它的 WebView 实际行为）；
  若还异常，升级系统 WebView（Chrome 73 → 新版）是一劳永逸的兜底建议。
- 本轮改的只是网页（App 的 WebView 加载服务器页面），**无需出包**；`?v=` 已熔断到 0.32.1。
