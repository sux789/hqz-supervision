# 036 - v0.44 迭代记录_环节内备注

## 1. 需求背景（用户原话）

> 如果某环节选择不正确，需要填 文本框，需要修改 excel 模板 ，最好实现 excel 模板 变化不改代码。

两处口径由用户当场拍板：

- 文本框位置：**环节就地展开**（不是弹窗、不是流程末尾统一备注）。
- 触发条件：**模板显式标记**（Excel 里写 `→备注≥N` 才展开，代码不猜哪些选项算"错"）。

## 2. 验证结果（改前数据对比/报错现场）

改前：`流程-整地` 第 1 环节「核实施工面积」选「不正确」后界面无任何输入框，直接点「通过」即可提交；
`流程-回塘底肥` 的「未实施施肥」「未达到每株1.5kg」同样只记录选项本身，没有强制说明。
流程级备注只在底部结论=不通过时出现，与「某一项核验不达标」是两回事，现场说明无处可写。

## 3. 设计方案（逻辑+口径依据，引用证据文件）

1. **复用已有 DSL，不加 Excel 行/列**：控件语法本来就允许 `选项(正确;不正确→备注≥2)`
   （`doc/030` 的控件约定、`tools/tpl/tpl_tool.py` 的说明页）。此前 `→` 后的规则只被附带展示，
   没有任何解析动作。现在把它变成唯一的开关：**`→备注≥N` = 该选项选中时，本环节就地展开
   一个隐藏文本框，要求 ≥N 个汉字**。
2. **解析期生成合成控件**（`flow_tpl.py`）：选项控件解析时收集所有带「备注」的规则 →
   `note_on` / `note_rules` / `note_name={环节}说明`；同一环节追加一条
   `hidden=True, show_on={触发控件: [错误项...]}, note_for=触发控件, min_chars=N` 的多行文本控件。
   字段名用「{环节}说明」，天然按环节隔离，落库回显不需要新表。
3. **显隐由模板驱动**：`show_on` 是`{字段: [选项]}` 映射，`v2CtrlShown` 只看值命中；
   没有 `show_on` 的老隐藏备注退回「结论=不通过才显示」，老模板行为不变（C28）。
4. **服务端权威**（C13）：只校验**当前应显示**的隐藏控件，并取该环节当前选中项对应的最小字数
   （模板可以给不同错误项写不同的 N）；`main.py` 与前端共用同一份 `note_rules`。
5. **切换回正向项即清空**：避免隐藏住的旧文字被一起提交（前端 clear + 重画）。

## 6. 反转记录（反转了哪条旧决策，为什么；无则写「无」）

- 反转「v2 备注只有流程级一条」：核验项不达标需要就地说明，流程级备注承担的是「整条结论」，
  两者混用会让一条不通过只能写一句总述。现在环节内备注按环节落库 `{环节}说明`，
  流程级备注仍只在结论=不通过时必填（C28③ 未变）。
- 明确「不新增 Excel 行列」：语法已有 `→备注≥N`，新增列会让业务专家多学一套配置；
  继续走"模板写规则、代码零改动"的路线（用户原始诉求）。
