# doc/022 — v0.33 轨迹按小班手动记录（C21 反转）

> 2026-10-16。用户明确反转 v0.32 的"授权即持续采集"：自动记录与间隔感知不合理，轨迹要按小班归属。

## 一、需求口径（用户原话归纳）
1. 轨迹数据仍**只来自卫星**（原生 GPS_PROVIDER，无网络定位——不变）；
2. **点「轨迹」= 开始记录当前小班**，数据归属当时的小班；
3. 自动采集不合理，**要点击才开始**；
4. 记录后要有**显示轨迹的地图按钮**；
5. 轨迹**可累加点**（同一小班多次行走叠加，直到结束上传）；
6. 后续**按小班导出轨迹 SHP**（本轮先把数据基础做好：文件名含小班）。

## 二、关于"15 秒一次"的核实
原生实际配置是 **GPS 1s / 2m**（`requestLocationUpdates(GPS_PROVIDER, 1000, 2f)`），
不是 15 秒。现场感知"十几秒一个点"的三个来源：
- **静止不动时不出点**——minDistance=2m 是刻意设计（抑制原地抖动毛团），站着不动点数不涨；
- 通知栏"已录 N 点"**10 秒节流**刷新；
- 林冠遮挡下 GPS 出 fix 本身慢（十几秒一个）。
结论：采样参数不动（1s/2m 已足够密），主要修"自动采→手动采"。

## 三、设计（v0.33）
### 原生（BgLocationPlugin，需出包 v0.11）
- **开关持久化在原生侧**（SharedPreferences `track_on`，默认关）——C21 精神保留：
  开关不随页面生死，页面重载/息屏/杀进程后按持久化状态恢复；
- 新增 `setTracking(on)`：on=需已授权+GPS 开（否则 reject），写 pref + startGps；
  off=stopGps（缓冲文件保留）；`stopWatcher` 同时清 pref（彻底停）；
- `load()/handleOnResume()` 只在 **track_on=true** 时恢复采集（v0.32 是无条件自启）；
- `status()` 增加 `trackOn` 字段；采样不变。

### 网页（app.js，?v=0.33）
- 按钮「▶ 记录轨迹」→ `setTracking(on)` + **归属快照 trackCls=当前小班**（localStorage
  `hqz_sup_track_cls` 同步，页面重载后恢复）→ 变红「⏹ 结束轨迹 N 点」；
- 点「⏹ 结束轨迹」→ 上传 GPX（**文件名 `轨迹_{归属小班}_{时间}.gpx`**，归属用快照不跟界面走），
  成功才 `setTracking(off)` 清点；失败（林区无网）点保留、可再点结束重试；
- 切小班/返回列表/开始录像 → 自动**结算原小班并停止**（v0.32 是"结算并续采"）；
- 「🗺 轨迹图」按钮（有累积点才出现）→ 纯 SVG 示意路径：等比缩放折线 + 绿起点/红终点 +
  点数/累计距离（haversine）/起始时间。**无底图、零依赖、离线可用**；
- 原生桥调用全部 `nativeTimeout` 限时（v0.32.7 教训延续）。

## 四、SHAP 导出（后续）的数据基础
轨迹上传文件名已固定含小班（`轨迹_{小班}_{ts}.gpx`，服务端按原名存 `data/tracks/`），
按小班导出 = 按文件名前缀归组 + GPX→SHP 转换（纯标准库写 .shp/.shx/.dbf polyline 可行，
后续单独立项）。
