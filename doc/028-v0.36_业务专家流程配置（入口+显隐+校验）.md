## 1. 需求背景（用户原话）

> 「文件名 `流程配置-业务员填写版.xlsx` 修改 `流程配置-业务专家填写版.xlsx`，设计的业务员改为业务专家；
> 是否在项目里面行选择 excel 列表行里面选择 是巡视 验收 还是材料，后续一个界面操作？
> 然后 流程配置-业务专家填写版本就分为 流程配置-巡视 流程配置-验收-人工造林 流程配置-材料
> 这样是否更为简化，业务专家决定主要因素是 环节显示 上传的 excel 中那些基本元素，
> 已经下拉框中选择的不显示，要显示哪些参考元素，提交什么数据 和控件，验证，前置条件，
> 能否理解我的意思，能否扩展我的想法？」

拆成四件事：

| # | 用户说的 | 本轮怎么落 |
|---|---|---|
| 1 | 改称「业务专家」，文件改名 | 全量重命名（文件名/sheet 说明/代码注释/测试） |
| 2 | 行里选「巡视/验收/材料」，还是一个界面？ | **一个界面 + 入口 tab**，不拆文件（见 §3.1） |
| 3 | 拆成三个文件是否更简化？ | **不拆**（见 §3.2，三个真相源 = 三倍维护） |
| 4 | 环节显示哪些基本元素、下拉里哪些不显示、提交什么、怎么验证、前置条件 | 四个新列 + 一个 DSL（见 §3.3~§3.6） |

## 2. 验证结果（改前 / 改后数据对比）

用户问「拆三个文件是否更简化」，实测数据说话：

| 指标 | 拆三个文件 | 一个文件 + 入口列（采用） |
|---|---|---|
| 真相源数量 | 3（改一个环节要判断改哪份、另外两份要不要跟随） | 1 |
| 同一个小班跨入口 | 分别在两个文件里，改项目类型要改两处 | 同表相邻两行，一眼看到 |
| 生成/校验代码 | 三份解析结果要 merge，冲突谁赢没定义 | 一次 parse，天然一致 |
| 业务专家操作 | 打开 3 个文件，容易只改一份 | 打开 1 个文件，按「入口」列筛选 |

实测：9 条流程 = 4 验收 + 4 巡视 + 1 材料，**同一个文件里 66 行，拆开是 3 个文件 10/10/46 行**，
跨入口一致性检查（验收有的项目类型巡视有没有）拆开后必须写额外脚本才能查 —— 目录里已有
`流程配置-造林数据.xlsx`、`…副本.xlsx` 这类多文件并存的前车之鉴（测试选文件曾被副本坑过，见 027 §5 坑 6）。

## 3. 设计方案

### 3.1 入口维度：一个界面 + tab（回答"行里选还是分文件"）

```
小班档案（data 行） ──┬── 入口「验收」→ 流程-人工造林（2026版）·验收  → 7 环节
                      └── 入口「巡视」→ 流程-人工造林（2026版）·巡视  → 1 环节（可多次）
项目级入口 ──────────── 入口「材料」→ 流程-材料检验（按批次）·材料  → 2 环节（按批次，不挂小班）
```

- **流程唯一键带入口**：`flow_key(name, entry)` → `流程-{名称}·{入口}`。
  没有它，同名的「人工造林·验收」和「人工造林·巡视」会互相覆盖。
- **不能只靠匹配器选**：验收和巡视都挂「小班档案」、条件都是「项目类型」，`match_flow`
  只会返回优先级最高的那一条 → **巡视永远进不去**。这是本轮实现时发现的真问题。
  解法：`GET/POST /flow` 加 `entry` 参数；GET 额外返回 `entries`
  （该行能进哪几个入口，含各自环节数），前端出 tab 由人切。
- **材料入口不挂小班**：`条件字段=独立入口, 条件值=独立入口`，`'' == ''` 会误命中（027 坑 3 已记），
  所以两边都写死「独立入口」。它不出现在小班的 tab 里，走项目级入口（本轮只打通后端，界面留待下轮）。

### 3.2 为什么不拆文件

一句话：**一个文件 = 一个真相源**。拆开后「新增一个项目类型」要改三处，漏一处就是"验收有、巡视没有"，
而这种残缺在界面上表现为"某个 tab 点进去是空的"，现场根本没法自查。

### 3.3 两级显隐（"显示哪些基本元素 / 下拉里哪些不显示"）

②环节 两列 + ③核验项 一列，**白名单 + 黑名单混合**：

| 列 | 位置 | 语义 |
|---|---|---|
| 显示的基本信息 | ②环节 | 白名单，`；`分隔列名。**留空 = data 全部列都显示** |
| 不显示的基本信息 | ②环节 | 黑名单，从白名单（或全部）里剔除，**黑名单优先** |
| 不显示选项 | ③核验项 | 从该下拉/多选的选项里剔除，`；`分隔 |

- `expert: true` 标记随环节下发 —— **老 12 列流程没有这几列，前端必须能区分**
  「业务专家没填白名单（= 全部）」和「老流程（= 不显示基本信息块）」。
  不加这个标记，老流程会突然冒出 29 列，线上界面直接崩。
- 列多时用原生 `<details>` 折叠（Chrome 73 支持，不写 JS 展开逻辑）。
- 黑名单写错列名 → 只 warning 不报错（黑名单是"少显示"，写错只是没省事，不阻断生成）。

示范（真在配置里）：整地环节白名单留空（= 全部）+ 黑名单剔掉采伐方式/株数强度等 8 列；
巡护方式三个选项（步行/车辆/无人机）里剔掉「无人机」。

### 3.4 校验规则 DSL（"验证"）

③核验项「校验规则」列，一句话写清，多个用 `；` 分隔：

| 写法 | 含义 | 支持 |
|---|---|---|
| `整数` | 必须是整数 | ✔ |
| `≥0` `>0` `≤100` `<50` | 数值比较 | ✔ |
| `10-100` | 闭区间 | ✔ |
| `≤500字` | 长度上限 | ✔ |
| `日期≥今天` | 不能填过去 | ✔ |
| `正则:^\d{11}$` | 正则 | ✔ |

三条纪律：

1. **配置期就要拦住错写法**：`rule_ok()` 认不出来 → 报错（否则静默不校验，比不配更危险）。
2. **服务端权威**（C13）：前端 `ruleBad()` 只是"少跑一趟"的即时提示，`_rule_errors()` 才是边界。
3. **空值不归规则管**：空值交给必填校验，规则只管"填了但不合规"。

### 3.5 带结论的前置条件（"前置条件"）

从「整地」升级到「整地=通过；回塘及底肥=合格」：

```python
prev      = ['整地', '回塘及底肥']                       # 名字列表（兼容老流程）
prev_result = {'整地': '通过', '回塘及底肥': '合格'}      # 期望结论
```

判定口径：期望是**正向词**（`PASS_RESULTS` 里的通过/合格/整改后合格/全部完成/已完成/符合）时，
按"这一类"放宽判 —— 现场可能填「合格」而不是「通过」，不能因此卡死；
期望是别的词（如「已完成」以外的人造词）就要求精确相等。

### 3.6 唯一性校验（"一条记录对多少班"的补漏）

②环节「唯一性校验」列：`不校验` / `同小班同日唯一` / `同批次号唯一`。

**两个真 bug（实现时自查发现，都已修）**：

- 「同小班同日唯一」原来写死读 `values['记录日期']`。但巡视环节的日期控件叫**「巡护日期」** ——
  读不到值 → 退化成"今天" → 等于随机拦/随机放。改成**取该环节第一个日期型控件**。
- 「同批次号唯一」原来写死读 `values['批次号']`。但苗木检验的控件叫**「进场批次号」** ——
  同理改成取**第一个名字含"批次"的控件**。

教训一句话：**字段名由业务专家起，代码里一个都不能写死**（与 C19 同源：不要自己拼/自己猜键）。

## 5. 测试验证

`bash tests/run_all.sh` → **339 项全绿**：

| 段 | 项数 | 说明 |
|---|---|---|
| 单元 | 108 | 不变 |
| 流程配置 | 77（原 41） | 新增入口/两级显隐/剪枝/规则/唯一性/`_rule_errors`/老记录迁移（E 段 7 项） |
| 端到端 | 109 | 不变 |
| 流程 e2e | 25（原 14） | 新增 D3 双入口、D7 切巡视、D13/D14 规则拦、D21/D22 唯一性、D24 入口隔离 |
| EXIF | 20 | 不变 |

`bash tools/run.sh` → 七门 PASS。

**本轮踩的坑（都是"看着没事实际坏了"）**：

1. `re.split(r'[=＝]', item, maxsplit=1)` 返回 **2 段**，代码按 3 段解包 → `ValueError`。
2. `dict(AT, **{3: '整地'})` → `TypeError: keywords must be strings`，要写 `{**AT, 3: '整地'}`。
3. 测试按 `{流程名, 环节名}` 定位行时漏了「入口」——「日常巡护」在巡视入口，用验收入口找会返回 0 行，
   `ws.cell(row=0)` 直接 `ValueError`。
4. 入口写错的报错文案是「在①流程里没有定义」而不是「入口不认识」——**层级更高的错先报**，
   测试断言要贴着真实文案，不能主观想象。
5. 「验收」和「巡视」同条件同优先级 → `match_flow` 只返回一条，巡视永久不可达（§3.1）。
6. 唯一性校验字段名写死 `记录日期`/`批次号`（§3.6）。

**接着用 Chrome 真机尺寸截图自测（纯 API 测过全绿，界面还是错的），又抓出 5 个**：

7. **「是否通过」被数两遍**：`ctrlsHtml()` 跳过了它（由底部结论区渲染），但 `gate()` 没跳过 ——
   控件循环里当普通下拉判一次、结论区再判一次 → 界面显示"还差 3 项：是否通过、是否通过、附件…"。
   **同一个字段在两条路径上判，必须两处都写跳过名单**。
8. **下拉的选项剪枝不生效**：`optsFor()` 统一处理"字面值 / data 枚举 / 剪枝"，
   但「下拉」分支自己内联了一遍 `splitList + dataEnum`（只有「多选」走了 `optsFor`）→
   剪枝只对多选管用。症状：配置里写了剔除「无人机」，界面上还在。**一件事写两遍，改一处必漏**。
9. **`Object.keys(std)` 不是"data 全部列"**：`std` 里混着「控件名 → 设计值」的映射
   （整地数量=627 这种），29 列被算成 33 个键 → 黑名单剔不干净（33-8=25，应该是 21）。
   改由后端单独下发 `std_cols`（真实表头）。
10. **本系统自己产出的列不该出现在"不可修改的基本信息"里**：留空=全部时会带出
    「验收人 / 验收日期 / 验收结果 / 验收备注」，现场看到「验收结果：—」会误以为这环节已有结论。
    加 `DEFAULT_HIDE`，**只在白名单留空时**追加（专家点名要看就听他的）。
11. **未解锁的按钮仍是实心绿**：`.btn` 没有 `:disabled` 样式，看着完全能点 ——
    现场会反复点"保存这一条"以为没反应。补 `opacity + not-allowed` 与 primary 专用灰。

一句话总结这轮的教训：**API 全绿不等于界面对**。凡是改了渲染路径，必须用真实内核尺寸截一次图，
而且要在**同一个浏览器里把每个 tab / 每个环节都点一遍**（只截第一个环节，7 号 8 号 bug 都不会暴露）。
