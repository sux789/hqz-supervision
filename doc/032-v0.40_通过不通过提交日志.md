# 032 - v0.40 迭代记录_通过/不通过提交日志

> 模板：`data/tpl-人工造林-验收流程模板.xlsx`（本次不改模板）
> 版本：v0.40 ｜ 日期：2026-10-27 ｜ 前置：doc/031（v0.39 参数页/独立巡护）

## 1. 需求背景（用户原话）

> 最后的 通过 不通过都保存 记录，独立流程则显示通过不通过 的记录 到当前页面日志区，放在最后，关联流程则可以解锁下一步，也添加日志区，日志记录经纬度 ip 时间 操作人等

拆成四条可验收项：

1. 每次点「通过 / 不通过」都留一条记录，不因重复提交丢失；
2. 独立流程（日常巡护）在当前页最下方列出历次结论；
3. 关联流程也有同样的日志区；「通过」仍按流程路由解锁下一步；
4. 日志每条带经纬度、IP、时间、操作人（及结论、第几次、环节数）。

## 2. 验证结果（改前数据对比/报错现场）

- `flow_records` 已写 `result/operator/geo/ip/created_at/updated_at`，但 GET `/flow` 只
  `SELECT step_no,rec_no,factor,value,att_json,result,operator,updated_at`，**geo/ip 没出库**；
- 页面 `renderV2` 以 `.flow-submit`（通过/不通过）结束，提交后没有日志区；独立流程只能从
  `multi`（rec_no>0）看到值，看不到操作人/IP/经纬度/提交时间；
- 非重复流程固定 `rec_no=0`，再次提交走 UPDATE 覆盖 → **上一次的通过/不通过结论被覆盖**，
  与“都保存记录”冲突；
- 审计值只在 `flow_records` 的 `factor=''` 行里，和历史填报值混在一张表，无法区分
  “提交事件”与“字段值”。

## 3. 设计方案（逻辑+口径依据）

| 决策 | 口径与依据 |
|---|---|
| 提交事件独立成表 | 新增 `flow_audit`：一次 `/flow/batch` 写一行（结论/操作人/geo/ip/环节数/时间/rec_no）。填报值仍走 `flow_records`（覆盖/新增语义不变），审计只追加、不改写 → 非重复流程重交也能保留历次结论 |
| 日志读法 | GET `/flow` 返回 `flow_log`：按 `flow_audit.id DESC` 取本工作簿+本行+本流程最近 100 条；老数据没有审计行时，从 `flow_records` 的 `factor=''` 行按 `rec_no` 归并兜底（`_flow_log_from_records`） |
| 展示位置 | `renderV2` 在 `.flow-submit` 之后追加 `.flow-log`，即页面最下方；可重复流程标「第 N 次」，非重复流程标「最近一次 / 历史 N」；经纬度为空显示「—」（室内无定位） |
| 解锁不变 | 解锁仍由 `_tpl_route_status` 读 `flow_records` 的 `verdict` 结论；审计是旁路，不参与闸门。独立流程照旧不阻塞、不解锁主线 |
| 清理 | `DELETE /api/workbooks/<id>?purge=1` 同步删 `flow_audit`；下架（软删）保留 |

## 6. 反转记录（反转了哪条旧决策，为什么）

1. **反转「非重复流程只保留最近一次」**：v0.38 起 `rec_no=0` 覆盖填报值，上一轮结论随之消失。
   用户要求“通过/不通过都保存”，故把**提交事件**拆到 append-only 的 `flow_audit`，
   填报值仍覆盖（现场纠错口径不变）。
2. **反转「审计信息只附在填报行上」**：geo/ip/operator 原来只写在 `factor=''` 的字段行，
   与业务值同表、按 rec_no 覆盖；现在每次提交独立一行，日志区不必再猜“哪一行代表一次提交”。
