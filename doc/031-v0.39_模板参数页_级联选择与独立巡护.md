## 1. 需求背景（用户原话）

> selectorBar 这个选择，标段放在 项目类型后面，小班放在最后面 ，实现级联选择；模板位置 /Users/sux/Desktop/hqz-supervision‌/data/tpl-人工造林-验收流程模板.xlsx，修改工具 ， /Users/sux/Desktop/hqz-supervision‌/tools/tpl/tpl_tool.py 可以修改模板以适配程序，比如添加参数sheet,程序有改动则添加到参数中，以后修改参数而程序不变，另外 日常巡护 流程 是 独立流程，可以多次填写，不影响其他有前后关系的流程。用同一的通过 不通过代替 提交？

拆成五条可验收项：

1. 搜索栏顺序固定为 项目类型 → 标段 → 乡（镇） → 村（社区） → 小班号（最后）；
2. 级联：前一项的选择过滤后一项的候选，改前项要清掉失效的后项；
3. 模板以仓库 `data/` 里的文件为准；`tools/tpl/tpl_tool.py` 能改模板适配程序（新增「参数」页），程序新增配置只补参数、不改代码；
4. 日常巡护是独立流程：可多次、不参与主线先后、不阻塞也不解锁其它流程；
5. 底部用统一的「通过 / 不通过」代替「提交」。

## 3. 设计方案（逻辑+口径依据）

| 决策 | 口径与依据 |
|---|---|
| 参数即配置 | 模板新增「参数」页（`key|value|类型|默认值|说明|示例`）。程序消费的 key 由 `PARAM_SPECS` 声明；`params` 命令只补缺失 key，**已有值不覆盖**（`--force` 才重置）→ 以后新增配置=加一行 + 跑命令，前端/后端不改 |
| 级联 | `搜索选项` 的顺序就是级联顺序。第 i 项选项 = 前 i-1 项过滤后的候选行集合；改前项后清掉失效的后项（`pruneAfter`），只剩 1 个候选时自动跳到那一行 |
| 独立流程 | 解析口径：`可重复=是` 且 `前置流程` 为空 → `independent`。路由排序把独立流程放最后；默认流程只在主线里选；`available` 恒为 True；不参与任何前置关系 |
| 提交语义 | 不再渲染「是否通过」环节卡片，也不再有单独「提交」。底部两个按钮把结论写进流程唯一的 `verdict` 控件再走 `/flow/batch`；点「不通过」先展开备注并校验 ≥2 汉字 |
| 模板位置 | 模板入库 `data/`；源表（5 个原始 sheet）移出仓库，`build` 必须显式 `--src`；日常改配置走 `params` |
| 模板体检 | `check_template.py` 识别 v2：`设计值`=数据表，`流程路由`/`说明`/`参数`/`流程-*` 为非数据页 |

## 6. 反转记录（反转了哪条旧决策，为什么）

1. **C28⑤「可重复流程永远可选（含默认）」→ 独立流程不参与默认**：巡护可重复，旧规则会让它成为默认，用户明确“不影响其他有前后关系的流程”。
2. **v0.38「提交」按钮 → 统一「通过 / 不通过」**：模板本来每条流程只有一个结论行，单独提交再选结论是两步；两个按钮把结论和提交合成一步，不通过时再展开备注。
3. **「模板不入库、参数靠代码兜底」→ 模板入库 + 参数页为配置源**：用户要求“以后修改参数而程序不变”，顺序/功能/唯一键必须能从模板读，不能再写死在 `_tpl_default_config`。
4. **代码里写死搜索顺序 → 级联由参数顺序驱动**：顺序即级联关系，改顺序只改 `参数` 页。
