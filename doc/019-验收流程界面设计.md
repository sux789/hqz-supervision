## 一、设计原则（承接 C01/C11「配置驱动」）

界面上每一个输入框、下拉、按钮，**都不是写死的**，而是由 Excel 三列推导出来：

| Excel 来源列 | 驱动什么 | 解析函数 |
|---|---|---|
| `流程-人工造林` 的 **`填报控件`** 列（第 12 列） | 该环节渲染什么控件、什么类型、什么校验规则 | `parseCtl()` |
| `流程-人工造林` 的 **`附件要求`** 列（第 8 列） | 该环节出哪些拍照/上传/打卡按钮、各几张 | `parseAtt()` |
| `验收流程` 注册表 | 这个小班该走哪条流程 | `matchFlow()` |
| `data` 表 + `标准值来源` 列 | 每个因子的标准值（自动带出、自动对照判合格） | `stdOf()` |
| `验收类型` / `填报要求` / `转序规则` / `通过标准` | 卡片头部的说明文字、提交闸门、环节解锁顺序 | 直接渲染 |

管理层改 Excel → 界面自动变，**程序零改动**（对齐既有 C01/C11 口径）。

## 二、界面结构（8 环节）

```
┌─────────────────────────────────────────┐
│ 验收 · 人工造林     7标段·YJ-1436·46.24亩 │  ← 顶栏 sticky
│ ①─②─③─④─⑤─⑥─⑦─⑧  步骤条（可横向滚动）  │
├─────────────────────────────────────────┤
│ [选择小班 ▾]  ← 模拟 data 行，演示流程匹配 │
│  小班号/类型/标段/年度/乡镇/村/面积/…     │
│  命中流程 · 优先级 · 条件                  │
├─────────────────────────────────────────┤
│ 环节卡片                                  │
│  标题 + 类型徽章 + 序号 n/8               │
│  备注 / 填报要求 / 校验方式 / 通过标准     │
│  ── 因子控件区（parseCtl 渲染）──         │
│  ── 附件按钮区（parseAtt 渲染）──         │
├─────────────────────────────────────────┤
│ 必填未完成 N 项：xxx   [提交本环节]       │  ← 未完成时置灰
└─────────────────────────────────────────┘
```

### 各环节的控件（逐条取自 Excel「填报控件」列）

| # | 环节 | 控件 |
|---|---|---|
| 1 | 小班边界确认 | 12 项逐条勾选框（带 data 标准值对照）＋ 验收人（自动，禁用）＋ 验收日期 |
| 2 | 整地 | 整地规格 **拆 3 个数值框**（长/宽/深，从 `60×60×50` 拆）＋ 整地方式下拉（选项从 data 该列去重） |
| 3 | 回塘及底肥放置 | 底肥用量（数值，>0）＋ 底肥品牌（单行文本 ≤20 字） |
| 4 | 栽植（苗木验收） | 苗龄 / 地径 / 苗高（数值，各自 ≥ 设计）＋ 种植数量（分批累计，超设计株数报红）＋ 混交比例实核 |
| 5 | 撑杆覆膜 | 完成情况下拉（符合设计 / 部分完成 / 未完成） |
| 6 | 成活率核验 | 抽查株数 + 死亡株数 → **成活率自动算**，不可手填 |
| 7 | 保存率核验 | 抽查株数 + 存活株数 → **保存率自动算** |
| 8 | 上一年度日常巡护 | 管护作业情况（4 项多选勾选）＋ 补植株数 ＋ 病虫害情况（下拉）＋ 问题描述（多行纯文本，=严重时必填） |

**跨环节通用**（底部固定）：验收结果（下拉）、验收人（自动取登录账号、不可改）、验收日期；选「整改后合格」时**动态插入**「整改期限」。

### 自动对照判合格（原型已实现）
- 整地规格：实测三项 ≥ 标准三项 → 绿字「对照通过」；任一 < 标准 → 红字
- 种植数量：累计 vs 设计总株数 → 显示还差多少株；超设计 → 红字
- 混交比例实核：与 data 设计值偏差 > 5 个百分点 → 红字
- 成活率 / 保存率：由抽查株数与死亡/存活株数**自动算**，只读展示

## 三、附件要求 → 按钮（两个解析层次）

### 3.1 正式语法（Excel 改成这样就精确解析）
```
拍照:整地现场照片@2          → 1 个拍照按钮，下限 2 张
上传:三证一签;拍照:剪苗作业  → 2 个按钮（半角分号分隔，可组合）
（留空）                     → 该环节无按钮
```
解析时用**括号感知分割**（`splitTop`）：分号只在括号外算分隔符，否则 `下拉(符合设计;部分完成;未完成)` 会被切成三段（这是原型开发中实测到的真 bug，已修）。

### 3.2 自然语言兜底（Excel 当前就是这么写的）
8 个环节的 `附件要求` 列全是自然语言，原型用规则表（`ATT_RULES`，**顺序敏感、命中即停**）解析。实测结果与原文完全对齐：

| 环节 | Excel 原文 | 解析出的按钮 |
|---|---|---|
| 1 小班边界确认 | `定位打卡 + 小班边界照片` | 📍定位打卡@1 ＋ 📷小班边界 |
| 2 整地 | `整地现场照片` | 📷整地现场 |
| 3 回塘底肥 | `回塘、放肥、覆土各 1 张照片` | 📷回塘 ＋ 📷放肥 ＋ 📷覆土@1 |
| 4 栽植 | `三证一签（需良种证的树种传四证一签）、种苗规格照片、剪苗作业照片` | 📎苗木证件@1 ＋ 📷种苗规格 ＋ 📷剪苗作业 |
| 5 撑杆覆膜 | `撑杆、覆膜照片` | 📷撑杆 ＋ 📷覆膜 |
| 6 成活率 | `成活率抽查照片` | 📷成活率抽查 |
| 7 保存率 | `竣工现场照片` | 📷竣工现场 |
| 8 日常巡护 | `巡护照片、巡护记录` | 📷巡护照片 ＋ 📎巡护记录@1 |

解析规则：
- 按 `、` `，` `＋` `+` 切片段，**一片 = 一个按钮**（贴近现场话术）
- 片段无任何关键词 → 并入上一片（处理 `撑杆、覆膜照片` 这种省略写法）
- `各 N 张` → 该片段按钮下限 N（并在冲突时给 ⚠ 提示）
- 兜底规则 `照片|现场` 放最后，避免重复追加一个"现场照片"按钮
- **加「定位打卡」按钮类型**（`punch`）：Excel 明确要求"定位打卡"，但既有 `功能` 参数只有 拍照/视频/轨迹，且现有 `◎ 轨迹` 是连续记录，语义不同 —— 打卡是"到此一游"的单点标记，需新按钮

### 3.3 防造假红线（沿用解说文档口径）
- **拍照** = App 内实时拍摄，**禁相册选图**，自动叠水印（坐标 + 项目 + 标段 + 小班号 + 时间 + 备注）
- **上传** = 可选照片或 PDF，但**操作人 / 时间 / 定位仍留痕**
- 两者走**同一条链路**：压缩参数、水印模板、目录、文件名模板全部复用现有「参数」sheet，不新增配置项

## 四、转序规则与提交闸门

| 环节 | 解锁条件（取自「转序规则」列） |
|---|---|
| 1 边界确认 | 无前置 |
| 2–5 各工序 | 上一环节**已提交**；且本环节必填项全填、附件达标 |
| 6 成活率 | **全部转序验收环节（2–5）合格后**方可进行 |
| 7 保存率 | 成活率验收**合格后** |
| 8 日常巡护 | 无转序前置（年度验收，平行） |

提交闸门 `gateOf()` 汇总所有未满足项，**在提交栏逐项列出**（如"底肥品牌、验收结果、附件"），而不是只说一句"请填写完整" —— 现场人员不用猜。

## 五、必须处理的数据坑（原型已全部处理）

| # | 坑 | 处理方式 |
|---|---|---|
| 1 | data 表头 `总株数  ` **末尾 2 个空格**（实测 key 长度 5） | `stdOf()` 遍历时 `keys[i].trim()===name` 统一 trim，否则取不到设计株数、种植数量校验失效 |
| 2 | 注册表第 2 行与第 6 行**同名「流程-人工造林」且优先级都是 10**，第 6 行自称演示行 | `matchFlow()` 的 `demo` 标记跳过演示行；真实接入时建议**从 Excel 删掉演示行**，否则人工造林被注册两次 |
| 3 | 第 2 行条件字段填 `1`（无条件）→ 现配置下 **600 行全部小班都跑人工造林**，含 188 行退化林修复 / 四旁植树 / 低效林改造 | 原型已如实呈现（选退化林修复小班也会进人工造林流程）。**这是配置问题不是代码问题**，需管理层把条件字段改成 `项目类型`、条件值 `人工造乔木林` |
| 4 | `验收结果选项` 参数页只写 `合格;不合格`，而「因子控件对照」定义了 `整改后合格` 并配了「整改期限」必填 | 原型按「因子控件对照」的 3 项渲染。**两者需对齐**，否则现场选了「整改后合格」但导出的选项里没有 |
| 5 | `混交比例` 列 number_format 被误设为 `h:mm`，Excel 里显示成 `0:17` | 界面按**原始数值** 0.29375 取用与显示，不走格式 |
| 6 | 「功能」参数 = `拍照;视频;轨迹`，但说明文字写「拍照、轨迹、**打卡**」 | 见 §3.2，需新增 `punch` 按钮类型与 `功能` 取值 |
| 7 | data 脏数据：项目类型 `人工造乔木林` 与 `人工造乔木林␣␣␣␣` 并存；乡镇「澧江街/澧江街道」、村「南昏/南昏村」双写 | 搜索/筛选下拉取值时 **trim + 去重归一**；条件匹配也须 trim 后精确等于 |

## 六、接入步骤（原型 → 真实 App）

原型是**单文件、零依赖、mock 数据**。接入分四步，每步都可独立验证：

### 步骤 1 · 后端出接口（新增 3 个只读接口）
```
GET /api/workbooks/<id>/flows              → 该工作簿的流程注册表 + 全部流程定义（按优先级排序）
GET /api/workbooks/<id>/flow?row=<ridx>    → 该行命中的流程 + 8 个环节定义 + 每个因子的标准值
GET /api/workbooks/<id>/flow/att?…         → 该环节已传附件清单（复用 photo_sync 的 kind 字段扩展）
```
- 解析逻辑放 `param_parser.py`（纯函数，可单测），复用 `parse_params` 的错误处理口径：**违规必须带 Excel 行号报错**（C02）
- 新增 sheet 定位：`验收流程`（固定名）+ 名称以 `流程-` 开头的表（**多 sheet 容忍**，不能像现在只取 1 个非「参数」sheet 那样报错）

### 步骤 2 · 新增积木（登记进 `BLOCKS.md`）
| 编号 | 职责 | 文件 |
|---|---|---|

| B20 | 流程填报界面渲染与闸门 | `static/flow.js` + `templates/index.html` |

### 步骤 3 · 前端接线

### 步骤 4 · 回归
