# 验收流程 Sheet 设计说明

> 依据：2026-10-09 会议录音（豆包/飞书两份智能纪要为同一次录音）。  
> 目标：把「按工序拆分的验收流程」做成 Excel 里的**参数化配置 sheet**，App 端读表驱动，**新增/调整流程不改程序**。  
> 状态：设计稿（不在开发流程内，独立文件夹存放）。原模板 `data/造林项目-验收模板.xlsx` 未改动，设计落在 `data/验收流程设计/造林项目-验收模板-含验收流程.xlsx`。

---

## 一、设计思路

现有模板已有 `参数` sheet（key/value 驱动拍照水印、可编辑列、下拉选项等），本次沿用同一套"配置驱动"思想，新增两类 sheet：

| Sheet 类型 | 命名规则                     | 作用                     | 数量    |
| -------- | ------------------------ | ---------------------- | ----- |
| 流程注册表    | 固定名 `验收流程`               | 登记**有哪些流程、对谁生效（条件）**   | 只 1 个 |
| 流程定义表    | 必须以 `流程-` 开头，如 `流程-人工造林` | 定义**一个流程内有哪些验收环节（工序）** | 可任意多个 |

- **加一个新流程 = 复制一个 `流程-XXX` sheet + 在 `验收流程` 表里加一行**，程序零改动。
- App 识别方式：sheet 名以 `流程-` 开头 → 是流程定义表；`验收流程` 是注册表。
- 对"某个文件"还是"全部文件"执行什么流程，由注册表 **适用范围** 列控制。

## 二、`验收流程` 注册表（7 列）

`流程sheet名 | 启用 | 条件字段 | 条件值 | 适用范围 | 优先级 | 备注`

### 条件语法（核心）

| 写法                                     | 含义                       |
| -------------------------------------- | ------------------------ |
| 条件字段 = `1`（或留空）                        | **无条件**，适用行全部执行此流程       |
| 条件字段 = `项目类型`，条件值 = `退化林修复`            | 只有该列值**等于**条件值的小班执行      |
| 条件值 = `退化林修复;四旁植树`                     | 多个候选值，半角分号分隔，**命中其一即执行** |
| 条件字段 = `项目类型;实施年度`，条件值 = `退化林修复;2026年` | 多条件**一一对应、全部满足**才执行      |
| 适用范围 = `全部`                            | 对所有工作簿文件生效               |
| 适用范围 = `造林项目-验收模板.xlsx`                | 只对该文件生效                  |

- **优先级**：数字越小越先匹配；一个小班命中多条流程时，按优先级取第一条执行（避免重复验收）。
- **启用 = 否**：临时停用某流程，不必删行；需要时改回"是"即可。

## 三、`流程-XXX` 流程定义表（11 列）

`序号 | 验收环节 | 验收类型 | 核验因子 | 标准值来源 | 填报要求 | 校验方式 | 附件要求 | 通过标准 | 转序规则 | 备注`

各列要点：

| 列     | 说明                                                                               |
| ----- | -------------------------------------------------------------------------------- |
| 验收类型  | `前置确认`（边界确认）/ `转序验收`（各工序）/ `完工验收`（成活率）/ `竣工验收`（保存率）/ `年度验收`（巡护）/ `抚育验收`          |
| 核验因子  | 该环节必查的因子清单，对应纪要中"必填项强制控制"——**填报要求=必填 的因子没填完，提交按钮置灰**                             |
| 标准值来源 | `data` 列名（如「整地规格」）= 从本底数据自动取标准值对照；`项目作业设计` = 无对应列、按方案人工判断。**本底数据全用户不可修改，仅作对照基准** |
| 填报要求  | `必填` / `选填`（可带条件，如"该列有值的小班必填"）                                                   |
| 附件要求  | 现场照片、三证一签/四证一签等；**仅限 App 内实时拍摄，禁止相册选图**                                          |
| 转序规则  | 环节间的先后约束；前置确认未通过不得进入第一个工序，全部转序验收合格才能做完工验收                                        |

## 四、示例文件内容（3 个流程）

以本模板 data 表 600 个小班的实际构成设计：

1. **流程-人工造林**（8 环节）：边界确认 → 整地 → 回塘及底肥放置 → 栽植（苗木验收）→ 撑杆覆膜 → 成活率 → 保存率 → 上一年度日常巡护。
2. **流程-退化林修复**（9 环节）：多一个**采伐修复**环节（标准值取 data 的采伐方式/株数强度/蓄积强度列），加**割灌割草**环节（该列有值的小班才填）。
3. **流程-四旁植树**（5 环节）：精简版。

每行的**备注列**已写清操作口径（分批填报、证件份数、确认人取登录账号等），现场人员照备注执行即可。

## 五、与现有 `参数` sheet 的关系

- `可编辑列`（验收人/验收日期/验收结果/验收备注）继续沿用；流程 sheet 只约束"怎么验、验什么"，**填报仍落在 data 的验收 4 列**。
- 若后续要按流程区分下拉选项（如不同流程的"验收结果选项"），可在 `参数` 的 key 上加流程前缀扩展（如 `流程-人工造林.验收结果选项`），本次不展开。

## 六、遗留注意事项（对接程序时再看，不属于本设计）

1. data 表头 `总株数` 原文**末尾带 2 个空格**，程序按列名匹配时必须 trim。
2. 条件匹配的取值比较建议 trim + 精确等于；枚举值以 data 实际取值为准（如 `补植修复+采伐修复` 是一个值）。
3. 分批填报、提交置灰、定位打卡、禁止相册选图为 App 端行为，流程 sheet 只负责"声明要求"。
4. 纪要中"监理日志自动生成、通知单联动、签字归档"是独立功能模块，与流程 sheet 解耦。
